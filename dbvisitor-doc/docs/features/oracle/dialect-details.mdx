# Oracle 方言细节

## 分页 SQL

Oracle 使用 ROWNUM 嵌套查询实现分页：

```sql
SELECT * FROM (
  SELECT TMP.*, ROWNUM ROW_ID FROM (
    原始查询
  ) TMP WHERE ROWNUM <= ?
) WHERE ROW_ID > ?
```

参数：`ROWNUM <= endRow` 和 `ROW_ID > startRow`。

## Count SQL

```sql
SELECT COUNT(*) FROM (原始查询) TEMP_T
```

注意：Oracle 的 count 子查询不使用 `as` 别名关键字，直接写 `TEMP_T`。

## 标识符引用

使用双引号 `"`：

```sql
SELECT * FROM "users" WHERE "name" = ?
```

## 写入冲突策略

| 策略 | SQL 语法 | 主键是否必须 |
|------|---------|:----------:|
| Into | `INSERT INTO ... VALUES (...)` | 否 |
| Ignore | `MERGE INTO ... USING (SELECT ... FROM dual) SRC ON (...) WHEN NOT MATCHED THEN INSERT ...` | 是 |
| Update | `MERGE INTO ... USING (SELECT ... FROM dual) SRC ON (...) WHEN MATCHED THEN UPDATE ... WHEN NOT MATCHED THEN INSERT ...` | 是 |

Oracle 的 MERGE 使用 `FROM dual` 作为虚拟源表。

## Generated Key 策略

Oracle 方言**统一使用 `OneByOne`**（逐条执行），无论是否有回填列、无论什么冲突策略。该选择不等于 Oracle JDBC 本身不支持 batch：

| 场景 | GeneratedKeyStrategy |
|------|---------------------|
| 所有场景 | `OneByOne` |

原因：Oracle JDBC 的 batch generated keys 行为不稳定。若使用 `Statement.RETURN_GENERATED_KEYS` 而不指定 `keyColumn`，返回的是 `ROWID` 伪列而非业务主键。

## 序列

Oracle 内置方言不实现 `SeqSqlDialect`，因此不能直接使用 `@KeySeq` + `KeyType.Sequence`。可在 Mapper XML 中使用 `selectKey`，或用 `@SelectKeySql` 执行以下语句：

```sql
SELECT user_info_seq.NEXTVAL AS id FROM dual
```

## 注意事项

- `RETURNING INTO` 是 OUT 参数模型，不等同于 PostgreSQL `RETURNING`，不能用 `generatedKeySource="resultSet"`
- INSERT 时应显式指定 `keyColumn` 才能正确回填业务主键
- 达梦的 MERGE 与 Oracle 语法高度一致（也使用 `FROM dual`）

## 关键差异总结

- 方言的插入执行策略均为 `OneByOne`
- 方言分页使用 ROWNUM 嵌套；如需其他分页 SQL，可自行编写 SQL 或提供自定义方言
- MERGE 使用 `FROM dual` 构造虚拟源表
- 不实现 `SeqSqlDialect`，序列走 `selectKey` 通道
