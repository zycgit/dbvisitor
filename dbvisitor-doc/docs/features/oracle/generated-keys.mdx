# Oracle 自增主键回填

Oracle 支持 `IDENTITY` 列，也长期使用 sequence 生成主键。两种方式在 dbVisitor 中的推荐配置不同：

- `IDENTITY`：插入后由数据库生成，使用 JDBC generated keys 回填。
- sequence：插入前先取序列值，再把主键值带入 INSERT。

Oracle JDBC 的 generated keys 行为和 MySQL、PostgreSQL 不完全一致。Oracle 官方文档说明，如果不显式指定 key columns，驱动无法判断要返回哪些生成列；使用 `Statement.RETURN_GENERATED_KEYS` 标志时，返回的是 `ROWID` 伪列。文档见 [Oracle JDBC Standards Support](https://docs.oracle.com/en/database/oracle/oracle-database/19/jjdbc/JDBC-standards-support.html)。

因此在 Oracle 下，使用 `IDENTITY` 回填业务主键时应显式配置 `keyColumn`。

## IDENTITY 列

Oracle 12c+ 可以使用 `IDENTITY` 列：

```sql
CREATE TABLE user_info (
    id   NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR2(64),
    age  NUMBER
)
```

JDBC 层推荐使用列名数组创建 `PreparedStatement`：

```java
PreparedStatement ps = conn.prepareStatement(
    "INSERT INTO user_info(name, age) VALUES (?, ?)",
    new String[] { "ID" }
);
ps.setString(1, "mali");
ps.setInt(2, 18);
ps.executeUpdate();

try (ResultSet rs = ps.getGeneratedKeys()) {
    if (rs.next()) {
        Number id = (Number) rs.getObject(1);
    }
}
```

dbVisitor 在 Mapper XML / Annotation 中通过 `keyColumn` 表达这个列名。

## Lambda / BaseMapper

Lambda 和 BaseMapper 的 INSERT SQL 由 dbVisitor 根据对象映射生成。Oracle 下如果实体主键使用 `KeyType.Auto`，dbVisitor 会按逐条执行方式插入，并使用 JDBC generated keys 回填。

```java title='Oracle IDENTITY 映射'
@Table("user_info")
public class UserInfo {
    @Column(value = "id", primary = true, keyType = KeyType.Auto)
    private Integer id;

    @Column("name")
    private String name;

    @Column("age")
    private Integer age;
}
```

```java title='Lambda 新增后读取回填主键'
UserInfo user = new UserInfo();
user.setName("mali");
user.setAge(18);

LambdaTemplate lambda = ...
int rows = lambda.insert(UserInfo.class)
                 .applyEntity(user)
                 .executeSumResult();

Integer id = user.getId();
```

Oracle 方言不会把有主键回填需求的 INSERT 优化成批量 generated keys；当前更稳妥的策略是 `OneByOne`，保证每条记录都能从 `getGeneratedKeys()` 中读取对应主键。

## Mapper XML

Mapper XML 是用户手写 SQL，dbVisitor 不会自动改写 SQL。Oracle `IDENTITY` 列使用 JDBC generated keys 时，应配置 `useGeneratedKeys`、`keyProperty` 和 `keyColumn`。

```xml title='Oracle IDENTITY generated keys'
<insert id="insertUser"
        useGeneratedKeys="true"
        keyProperty="id"
        keyColumn="id">
    INSERT INTO user_info (name, age)
    VALUES (#{name}, #{age})
</insert>
```

`keyColumn="id"` 是 Oracle 下的关键配置。它会让底层使用列名数组创建 `PreparedStatement`，从而让 Oracle JDBC 返回业务主键列，而不是只返回 `ROWID`。

## Annotation Mapper

注解方式同样应显式配置 `keyColumn`：

```java
@Insert(
    value = "INSERT INTO user_info (name, age) VALUES (#{name}, #{age})",
    useGeneratedKeys = true,
    keyProperty = "id",
    keyColumn = "id"
)
int insertUser(UserInfo user);
```

这里不需要配置 `generatedKeySource = GeneratedKeySource.ResultSet`。Oracle `IDENTITY` 的推荐方式是从 JDBC `getGeneratedKeys()` 读取。

## Sequence

如果表主键由 sequence 生成，最稳妥的方式是在 INSERT 前先取序列值。

```xml title='Mapper XML 使用 selectKey'
<insert id="insertUser">
    <selectKey keyProperty="id" keyColumn="id" order="BEFORE">
        SELECT user_info_seq.NEXTVAL AS id FROM dual
    </selectKey>
    INSERT INTO user_info (id, name, age)
    VALUES (#{id}, #{name}, #{age})
</insert>
```

注解方式可以使用 `@SelectKeySql`：

```java
@SelectKeySql(
    value = "SELECT user_info_seq.NEXTVAL AS id FROM dual",
    keyProperty = "id",
    keyColumn = "id",
    order = Order.Before
)
@Insert("INSERT INTO user_info (id, name, age) VALUES (#{id}, #{name}, #{age})")
int insertUser(UserInfo user);
```

Lambda / BaseMapper 可以直接使用 `KeyType.Sequence`：

```java
@Table("user_info")
public class UserInfo {
    @KeySeq("user_info_seq")
    @Column(value = "id", primary = true, keyType = KeyType.Sequence)
    private Integer id;
}
```

这种方式属于插入前生成主键，不依赖 Oracle JDBC generated keys。

## RETURNING INTO

Oracle 支持 `RETURNING ... INTO`：

```sql
INSERT INTO user_info(name, age)
VALUES (?, ?)
RETURNING id INTO ?
```

但这不是普通 `executeQuery()` 返回 `ResultSet` 的模型，通常需要注册 OUT 参数或使用 Oracle JDBC 专有 API。dbVisitor 的 Mapper XML / Annotation 中，`generatedKeySource="resultSet"` 适合 PostgreSQL `RETURNING`、SQL Server `OUTPUT INSERTED` 这类当前执行直接返回结果集的语法，不适合 Oracle `RETURNING ... INTO`。

因此 Oracle 下不要把下面这种写法当作普通 XML insert 使用：

```xml title='不推荐'
<insert id="insertUser"
        useGeneratedKeys="true"
        keyProperty="id"
        keyColumn="id"
        generatedKeySource="resultSet">
    INSERT INTO user_info(name, age)
    VALUES (#{name}, #{age})
    RETURNING id INTO ?
</insert>
```

如果确实需要使用 `RETURNING ... INTO`，应通过更贴近 Oracle 调用模型的专用代码处理 OUT 参数；普通 Mapper INSERT 推荐使用 `keyColumn` + JDBC generated keys，或使用 sequence + `selectKey`。

## 方言策略

Oracle 当前策略如下：

| 场景 | GeneratedKeyStrategy |
| --- | --- |
| 无回填列 | `OneByOne` |
| `Into` + 有回填列 | `OneByOne` |
| `Ignore` + 有回填列 | `OneByOne` |
| `Update` + 有回填列 | `OneByOne` |

Oracle 方言当前不把 INSERT 选择为 JDBC batch 路径。`DuplicateKeyStrategy.Ignore` / `Update` 由 `MERGE` 实现，需要主键列。

## 设计原则

- `IDENTITY`：配置 `keyColumn`，从 JDBC `getGeneratedKeys()` 回填。
- sequence：优先使用 `selectKey` / `@SelectKeySql` / `KeyType.Sequence` 在 INSERT 前取值。
- `RETURNING ... INTO`：属于 Oracle 专有 OUT 参数模型，不等同于 PostgreSQL `RETURNING`。
- Lambda / BaseMapper：Oracle 主键回填保守逐条执行，优先保证回填语义正确。
