# ClickHouse 方言细节

## 分页 SQL

ClickHouse 使用 `LIMIT ? OFFSET ?`（与 PostgreSQL 相同）：

```sql
SELECT ... LIMIT ? OFFSET ?
```

## Count SQL

```sql
SELECT COUNT(*) FROM (原始查询) as TEMP_T
```

## 标识符引用

使用双引号 `"`：

```sql
SELECT * FROM "users" WHERE "name" = ?
```

## 写入冲突策略

ClickHouse **不支持** Ignore / Update 冲突策略：

| 策略 | 是否支持 | 说明 |
|------|:------:|------|
| Into | ✓ | 普通 INSERT |
| Ignore | ✗ | 不支持 |
| Update | ✗ | 不支持 |

ClickHouse 是分析型数据库，不存在传统 OLTP 数据库的主键冲突概念。

## Generated Key 策略

| 场景 | GeneratedKeyStrategy |
|------|---------------------|
| 无回填列 | `JdbcBatch` |
| 有回填列 | `OneByOne` |

**不推荐依赖 JDBC generated keys**。ClickHouse 不使用数据库自增主键模型，业务标识应由应用侧生成（UUID、雪花 ID 等）。

## 序列

不支持。ClickHouse 不实现 `SeqSqlDialect`。

## 写入建议

- ClickHouse 推荐批量写入而非逐条插入
- 无回填需求时可利用 `JdbcBatch` 提升吞吐
- 注意异步写入特性：写入后未必立即可见
- 推荐主键生成方式：`KeyType.UUID32` 或 `KeyType.UUID36`

## 关键差异总结

- 唯一不支持任何冲突策略的关系型数据源
- 不推荐依赖 JDBC generated keys
- 不支持序列
- 分析型写入模型（批量优先，异步可见）
