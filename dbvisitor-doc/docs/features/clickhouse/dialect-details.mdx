# ClickHouse 方言细节

## 分页 SQL

ClickHouse 方言使用 `LIMIT offset, count`；offset 为 0 时仅追加 `LIMIT count`：

```sql
SELECT ... LIMIT ?, ?
```

## Count SQL

```sql
SELECT COUNT(*) FROM (原始查询) as TEMP_T
```

## 标识符引用

方言使用反引号：

```sql
SELECT * FROM `users` WHERE `name` = ?
```

## 写入冲突策略

ClickHouse **不支持** Ignore / Update 冲突策略：

| 策略 | 是否支持 | 说明 |
|------|:------:|------|
| Into | ✓ | 普通 INSERT |
| Ignore | ✗ | 不支持 |
| Update | ✗ | 不支持 |

ClickHouse 是分析型数据库，不存在传统 OLTP 数据库的主键冲突概念。

## Generated Key 策略

| 场景 | GeneratedKeyStrategy |
|------|---------------------|
| 无回填列 | `JdbcBatch` |
| 有回填列 | `OneByOne` |

**不推荐依赖 JDBC generated keys**。ClickHouse 不使用数据库自增主键模型，业务标识应由应用侧生成（UUID、雪花 ID 等）。

## 序列

不支持。ClickHouse 不实现 `SeqSqlDialect`。

## 写入建议

- ClickHouse 推荐批量写入而非逐条插入
- 无回填需求时可利用 `JdbcBatch` 提升吞吐
- 写入可见性取决于表引擎和设置。启用 `async_insert` 且关闭 `wait_for_async_insert` 时，响应可在数据落入表前返回；这不是所有 INSERT 的默认行为。见[异步写入说明](https://clickhouse.com/docs/optimize/asynchronous-inserts)。
- 推荐主键生成方式：`KeyType.UUID32` 或 `KeyType.UUID36`

## 关键差异总结

- 方言只提供普通 Into 写入，不提供 Ignore/Update 冲突策略
- 不推荐依赖 JDBC generated keys
- 不支持序列
- 分析型写入模型，通常应合并多行提交
