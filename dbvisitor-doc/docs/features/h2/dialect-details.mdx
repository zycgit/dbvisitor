# 方言细节

## 分页 SQL

H2 使用 `LIMIT ? OFFSET ?`（与 PostgreSQL 相同）：

```sql
SELECT ... LIMIT ? OFFSET ?
```

## Count SQL

```sql
SELECT COUNT(*) FROM (原始查询) as TEMP_T
```

## 标识符引用

使用双引号 `"`：

```sql
SELECT * FROM "users" WHERE "name" = ?
```

## 写入冲突策略

| 策略 | SQL 语法 | 主键是否必须 |
|------|---------|:----------:|
| Into | `INSERT INTO ... VALUES (...)` | 否 |
| Ignore | `MERGE INTO ... USING (VALUES ...) ... WHEN NOT MATCHED THEN INSERT ...` | 是 |
| Update | `MERGE INTO ... KEY (...) VALUES (...)` | 是 |

Ignore 使用带匹配条件的 MERGE，只插入未匹配记录；Update 使用 H2 的 `MERGE INTO ... KEY (...) VALUES (...)` 写法。

## Generated Key 策略

| 场景 | GeneratedKeyStrategy |
|------|---------------------|
| 无回填列 | `JdbcBatch` |
| 有回填列（任何策略） | `OneByOne` |

## 序列

H2 实现了 `SeqSqlDialect`，使用与 DB2 相同的语法：

```sql
VALUES NEXT VALUE FOR user_seq
```

## 测试场景建议

- 本地开发可使用 `jdbc:h2:mem:demo;DB_CLOSE_DELAY=-1` 创建内存数据库
- H2 兼容模式可模拟 MySQL/PostgreSQL 行为
- 但注意分页语法与真实数据库可能存在差异
- 不要用 H2 的兼容模式替代目标数据库的类型、事务和 SQL 行为验证

## 关键差异总结

- 分页语法与 PostgreSQL 一致（`LIMIT ? OFFSET ?`）
- Ignore 和 Update 使用不同的 MERGE 形式
- 支持序列（与 DB2 语法一致：`VALUES NEXT VALUE FOR`）
- 有回填时统一逐条执行
- 支持内存数据库，适合无需独立服务的本地开发
