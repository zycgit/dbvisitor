# H2 方言细节

## 分页 SQL

H2 使用 `LIMIT ? OFFSET ?`（与 PostgreSQL 相同）：

```sql
SELECT ... LIMIT ? OFFSET ?
```

## Count SQL

```sql
SELECT COUNT(*) FROM (原始查询) as TEMP_T
```

## 标识符引用

使用双引号 `"`：

```sql
SELECT * FROM "users" WHERE "name" = ?
```

## 写入冲突策略

| 策略 | SQL 语法 | 主键是否必须 |
|------|---------|:----------:|
| Into | `INSERT INTO ... VALUES (...)` | 否 |
| Ignore | `MERGE INTO ...` | 是 |
| Update | `MERGE INTO ...` | 是 |

H2 的 MERGE 语法与 Oracle/DB2 不同：使用 H2 自有的 `MERGE INTO` 语法。

## Generated Key 策略

| 场景 | GeneratedKeyStrategy |
|------|---------------------|
| 无回填列 | `JdbcBatch` |
| 有回填列（任何策略） | `OneByOne` |

## 序列

H2 实现了 `SeqSqlDialect`，使用与 DB2 相同的语法：

```sql
VALUES NEXT VALUE FOR user_seq
```

## 测试场景建议

- 本地开发推荐使用 `-Dnxn.env=h2`（无需 Docker）
- H2 兼容模式可模拟 MySQL/PostgreSQL 行为
- 但注意分页语法与真实数据库可能存在差异
- H2 的 `IDENTITY` 与 MySQL `AUTO_INCREMENT` 行为基本一致

## 关键差异总结

- 分页语法与 PostgreSQL 一致（`LIMIT ? OFFSET ?`）
- MERGE 语法为 H2 自有，与 Oracle/DB2 不同
- 支持序列（与 DB2 语法一致：`VALUES NEXT VALUE FOR`）
- 有回填时统一逐条执行
- 最推荐的本地测试数据库
