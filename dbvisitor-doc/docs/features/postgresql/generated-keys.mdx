# 自增主键回填

PostgreSQL 支持 JDBC generated keys，也支持原生 `INSERT ... RETURNING <column>`。对于单行 INSERT，两种方式通常都可以工作；对于多行 INSERT 后需要逐行回填主键，`RETURNING` 更适合表达 PostgreSQL 的原生能力。

```sql
INSERT INTO user_info (name, age, email)
VALUES (?, ?, ?)
RETURNING id
```

多行 INSERT 也可以一次返回多行主键：

```sql
INSERT INTO user_info (name, age, email)
VALUES (?, ?, ?), (?, ?, ?), (?, ?, ?)
RETURNING id
```

这条 SQL 的返回值表现为当前执行返回的 `ResultSet`。

## Lambda / BaseMapper

Lambda 和 BaseMapper 的 INSERT SQL 由 dbVisitor 根据对象映射生成，因此 PostgreSQL 方言可以在多行主键回填场景下选择 `RETURNING`，并从当前 `ResultSet` 回填主键。

```java title='Lambda 新增后读取回填主键'
UserInfo user = new UserInfo();
user.setName("mali");
user.setAge(18);

LambdaTemplate lambda = ...
int rows = lambda.insert(UserInfo.class)
                 .applyEntity(user)
                 .executeSumResult();

Integer id = user.getId();
```

```java title='BaseMapper 新增后读取回填主键'
BaseMapper<UserInfo> mapper = session.createBaseMapper(UserInfo.class);

UserInfo user = new UserInfo();
user.setName("mali");
user.setAge(18);

int rows = mapper.insert(user);
Integer id = user.getId();
```

多行插入且需要主键回填时，PostgreSQL 方言可以生成类似下面的 SQL：

```sql
INSERT INTO user_info (name, age)
VALUES (?, ?), (?, ?), (?, ?)
RETURNING id
```

## Mapper XML

Mapper XML 是用户手写 SQL，dbVisitor 不会自动追加 `RETURNING`。如果希望通过 PostgreSQL `RETURNING` 回填主键，需要在 SQL 中明确写出 `RETURNING`，并声明 generated key 从当前结果集读取。

```xml title='PostgreSQL RETURNING'
<insert id="insertUser"
        useGeneratedKeys="true"
        keyProperty="id"
        keyColumn="id"
        generatedKeySource="resultSet">
    INSERT INTO user_info (name, age, email)
    VALUES (#{name}, #{age}, #{email})
    RETURNING id
</insert>
```

多列回填也应显式列出：

```xml
<insert id="insertOrder"
        useGeneratedKeys="true"
        keyProperty="id,orderNo"
        keyColumn="id,order_no"
        generatedKeySource="resultSet">
    INSERT INTO user_order (user_id, amount)
    VALUES (#{userId}, #{amount})
    RETURNING id, order_no
</insert>
```

`generatedKeySource="resultSet"` 表示 generated key 从当前 `ResultSet` 读取，适合配合 PostgreSQL `RETURNING` 使用。

## Annotation Mapper

Annotation 中同样由用户负责写出 PostgreSQL 专有语法：

```java
@Insert(
    value = """
        INSERT INTO user_info (name, age, email)
        VALUES (#{name}, #{age}, #{email})
        RETURNING id
        """,
    useGeneratedKeys = true,
    keyProperty = "id",
    keyColumn = "id",
    generatedKeySource = GeneratedKeySource.ResultSet
)
int insertUser(UserInfo user);
```

如果不使用 `RETURNING`，则继续使用普通 JDBC generated keys：

```java
@Insert(
    value = "INSERT INTO user_info (name, age) VALUES (#{name}, #{age})",
    useGeneratedKeys = true,
    keyProperty = "id",
    keyColumn = "id"
)
int insertUser(UserInfo user);
```

## ON CONFLICT

PostgreSQL 的 `ON CONFLICT` 是冲突处理语法，不等同于普通 INSERT。手写 SQL 时，如果需要在冲突处理后返回主键，也应明确写出 `RETURNING`：

```xml
<insert id="upsertUser"
        useGeneratedKeys="true"
        keyProperty="id"
        keyColumn="id"
        generatedKeySource="resultSet">
    INSERT INTO user_info (id, name, age)
    VALUES (#{id}, #{name}, #{age})
    ON CONFLICT (id) DO UPDATE
    SET name = EXCLUDED.name,
        age = EXCLUDED.age
    RETURNING id
</insert>
```

如果由 Lambda / BaseMapper 生成 `ON CONFLICT DO UPDATE`，dbVisitor 会避免把冲突键列也写入 `SET`。

## 方言策略

PostgreSQL 当前策略如下：

| 场景 | GeneratedKeyStrategy |
| --- | --- |
| 无回填列 | `JdbcBatch` |
| `Into` + 有回填列 | `MultiValuesResultSet` |
| `Ignore` + 有回填列 | `OneByOne` |
| `Update` + 有回填列 | `MultiValuesResultSet` |

`DuplicateKeyStrategy.Ignore` 使用 `ON CONFLICT DO NOTHING`，不要求传入主键列列表；`DuplicateKeyStrategy.Update` 使用 `ON CONFLICT (<primary key>) DO UPDATE`，需要主键列且至少有一个非主键列可更新。

## selectKey

如果希望完全避开 JDBC generated keys 和 `RETURNING` 差异，可以使用 `selectKey` / `@SelectKeySql` 先读取序列值，再执行 INSERT。

```xml
<insert id="insertUser">
    <selectKey keyProperty="id" order="BEFORE">
        SELECT nextval('user_info_id_seq')
    </selectKey>
    INSERT INTO user_info (id, name, age)
    VALUES (#{id}, #{name}, #{age})
</insert>
```

这种方式适合业务希望先拿到主键，再执行 INSERT 的场景。

## 设计原则

- Lambda / BaseMapper：SQL 由框架生成，可以由 PostgreSQL 方言生成多行 `VALUES` 和 `RETURNING`。
- XML / Annotation：SQL 由用户编写，dbVisitor 不自动追加 `RETURNING`；需要用户显式写出 `RETURNING`。
- Session / JDBC 原始 SQL：保持忠实执行，不猜测当前 `ResultSet` 是否是 generated keys。
