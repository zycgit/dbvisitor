# 事务支持

## 多条写入一致性 {#write-consistency}

假设两条记录需要一起保存，第二条失败时，第一条也不能留下。下面使用一张空表，`id` 为主键：

```sql
CREATE TABLE user_info (
    id INTEGER NOT NULL PRIMARY KEY,
    name VARCHAR(100)
);
```

下面两次调用故意使用相同的主键：

```java
import net.hasor.dbvisitor.jdbc.core.JdbcTemplate;

JdbcTemplate jdbc = new JdbcTemplate(dataSource);
jdbc.executeUpdate("INSERT INTO user_info (id, name) VALUES (?, ?)",
        new Object[] { 1001, "Alice" });
jdbc.executeUpdate("INSERT INTO user_info (id, name) VALUES (?, ?)",
        new Object[] { 1001, "Bob" });
```

未开启事务、连接使用自动提交时，Alice 先插入并提交。随后 Bob 因主键重复而报错，但 Alice 不会自动撤销。

要在失败时全部回滚，重新从空表开始，将两次调用放入事务：

```java
import net.hasor.dbvisitor.transaction.TransactionTemplate;
import net.hasor.dbvisitor.transaction.TransactionTemplateManager;
import net.hasor.dbvisitor.transaction.support.TransactionHelper;

TransactionTemplate tx = new TransactionTemplateManager(
        TransactionHelper.txManager(dataSource));

tx.execute(status -> {
    jdbc.executeUpdate("INSERT INTO user_info (id, name) VALUES (?, ?)",
            new Object[] { 1001, "Alice" });
    jdbc.executeUpdate("INSERT INTO user_info (id, name) VALUES (?, ?)",
            new Object[] { 1001, "Bob" });
    return null;
});
```

Bob 插入失败后，异常传出回调，Alice 的插入也随之回滚，表中不会留下这两条记录。将第二条的 ID 改为 `1002`，两次插入成功后一起提交。

:::caution[注意]
`jdbc` 和事务管理器必须使用同一个 `dataSource`。不要在回调内捕获异常后直接正常返回；必须捕获时，调用 `status.setRollback()` 标记回滚。
:::

调用方法需处理或声明 `execute` 抛出的 `Throwable`。构造器 API 和 Mapper 也可以参与事务，完整配置见[事务模板](../../guides/transaction/template.md)。


## 设置隔离级别 {#isolation}

Db2 的名称与 JDBC 枚举不完全相同：READ_UNCOMMITTED 对应 UR，READ_COMMITTED 对应 CS，REPEATABLE_READ 对应 RS，SERIALIZABLE 对应 RR。需要 Db2 的 RR 时应选择 `Isolation.SERIALIZABLE`，不要按名称选择 REPEATABLE_READ。`Isolation.DEFAULT` 保留当前连接设置。 见[数据库隔离级别说明](https://www.ibm.com/docs/en/db2/12.1?topic=applications-data-server-driver-jdbc-sqlj-isolation-levels)。

例如，在上面的事务模板中用 SERIALIZABLE 执行查询：

```java
import net.hasor.dbvisitor.transaction.Isolation;
import net.hasor.dbvisitor.transaction.Propagation;

tx.execute(status -> {
    return jdbc.queryForList("SELECT id, name FROM user_info");
}, Propagation.REQUIRED, Isolation.SERIALIZABLE);
```
