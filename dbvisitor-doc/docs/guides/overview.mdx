# 1. 介绍

{/* llms:start */}

**dbVisitor 是基于 JDBC 标准构建的统一数据访问基座，核心理念是 One Access，愿景是 “One APIs Access Any DataBase”。** 它面向结构化、半结构化和非结构化数据的存储与检索场景，让 Java 应用以统一 API 或一致的编程风格访问关系型、文档、键值、搜索和向量数据库。

例如，一个应用可以用 MySQL 保存业务记录、MongoDB 保存文档、Redis 保存缓存、Elasticsearch 检索内容、Milvus 检索向量，同时复用参数绑定、结果映射、Mapper 和连接访问方式。One Access 的目标是降低接入不同类别数据源的学习与维护成本，让新增数据源能够接入已有的数据访问方式。

## 双层适配器架构

| 层次 | 职责 | 实现方式 |
| --- | --- | --- |
| 应用适配层：统一“怎么操作” | 统一业务代码中的访问 API，管理查询语法与数据映射差异 | `LambdaTemplate` 和 `BaseMapper` 按方言生成 SQL 或目标命令；Mapper 注解与 XML 组织 SQL/DSL；`JdbcTemplate` 执行驱动支持的 SQL、DSL 或原生命令 |
| 协议适配层：统一“怎么接入” | 将数据源协议接入 JDBC 的连接、语句、参数与结果接口 | 关系型数据库使用厂商 JDBC 驱动；`jdbc-mongo`、`jdbc-elastic`、`jdbc-redis`、`jdbc-milvus` 将对应数据库的 SDK/协议适配为 JDBC 驱动 |

两层通过 JDBC 衔接：业务代码使用应用层 API，应用层通过 JDBC 调用驱动，驱动访问目标数据源。应用层的多种 API 共享底层机制；驱动层也可独立供其他 JDBC 工具使用。这样既能统一完整的数据访问层，也能在现有项目中单独接入某个驱动适配器。

接入新数据源时，可基于 `dbvisitor-driver` 实现[自定义 JDBC 适配器](../drivers/dev/about.md)，继续复用上层访问方式；需要构造器能力时，再提供对应的数据库方言。

## 数据模型与访问场景

| 数据模型或场景 | 代表数据源 | 接入方式与能力入口 |
| --- | --- | --- |
| 结构化记录与关系查询 | MySQL、PostgreSQL、Oracle 等 | 厂商 JDBC 驱动；[按数据源查看能力](../features/overview.md) |
| 文档与半结构化数据 | MongoDB | `jdbc-mongo`；[文档操作与映射](../features/mongo/about.md) |
| 键值、缓存与数据结构 | Redis | `jdbc-redis`；[命令访问与结果映射](../features/redis/about.md) |
| 内容搜索与非结构化文本检索 | Elasticsearch | `jdbc-elastic`；[搜索、Query DSL 与索引操作](../features/elastic/about.md) |
| 向量与相似性检索 | Milvus | `jdbc-milvus`；[集合、标量过滤与向量操作](../features/milvus/about.md) |

One Access 遵循“承认差异、管理差异”的原则：统一调用方式、参数绑定和结果接收，并保留数据源的原生能力。具体命令、构造器、事务、批处理和分页能力以[数据源差异](../features/overview.md)为准。例如，Redis 使用 `JdbcTemplate` 或 Mapper 执行命令，当前没有构造器方言。

## 按需求选择 API

| 需求 | 入口 | 继续阅读 |
| --- | --- | --- |
| 已有 SQL、DSL 或原生命令，需要绑定参数并读取结果或更新数据 | `JdbcTemplate`；查询用 `queryForList`、`queryForObject`，修改用 `executeUpdate` | [编程式 API](./api/jdbc.md) |
| 希望在支持的不同数据源上复用条件构造与 CRUD 写法 | `LambdaTemplate` 或 `BaseMapper`；由对应方言生成 SQL 或目标命令 | [构造器 API](./api/lambda.md) |
| 希望用 Java 接口组织 DAO，集中管理 SQL/DSL | `Session.createMapper(...)`；方法注解、`BaseMapper` 通用 CRUD、XML 可组合 | [Mapper API](./api/mapper.md) |
| 数据载体使用 Map | 区分复用实体映射的 Map 模式与直接使用表名、列名的 Freedom 模式 | [Map 查询](./core/map_query/about.md) |
| 需要向量相似性查询 | 根据数据源方言选择支持的 KNN 排序或范围过滤 | [向量查询](./core/vector_query/about.md) |

`Configuration` 创建 `Session`，由 `Session` 创建 Mapper 接口实例。模板、Mapper 和构造器可在同一应用中组合使用；选择统一构造器或原生命令时，根据目标数据源的能力决定。

## 选择依赖和运行环境

使用完整双层架构时，引入 `net.hasor:dbvisitor` 和目标 JDBC 驱动：关系型数据库选择厂商驱动，NoSQL 或向量数据库选择对应的 `jdbc-*` 适配器。需要保留现有 Spring JDBC、MyBatis 等访问方式时，也可单独使用[驱动适配器](../drivers/about)，按该驱动支持的命令与 JDBC 能力接入。

dbVisitor 可直接嵌入普通 Java 应用，也提供框架集成：Spring Boot 用 `dbvisitor-spring-starter`，普通 Spring 用 `dbvisitor-spring`，Hasor 用 `dbvisitor-hasor`，Solon 用 `dbvisitor-solon-plugin`，Guice 用 `dbvisitor-guice`；这些发布模块的 groupId 均为 `net.hasor`。

## 完成第一次调用

1. 确定数据模型与目标数据源，选择驱动和运行环境依赖，准备 `DataSource` 或 `Connection`，以及表、集合、索引等目标资源。
2. 在方言支持时，通过 `new LambdaTemplate(dataSource)` 复用条件构造写法；已有 SQL/DSL 或命令时使用 `new JdbcTemplate(dataSource)`。需要 Mapper 时，通过 `new Configuration().newSession(dataSource)` 获取 Session。
3. 根据单行、多行、标量或 Map 结果选择重载，使用参数绑定传入值，并处理返回值和异常。
4. 明确连接与事务由谁管理。独立应用负责资源关闭；框架应用使用集成提供的对象和事务方式，避免另外创建一套连接环境。

起步代码见 [普通 Java 项目](./yourproject/with_java.mdx)；框架项目继续阅读 [Spring](./yourproject/with_spring.mdx)、[Hasor](./yourproject/with_hasor.mdx)、[Solon](./yourproject/with_solon.mdx) 或 [Guice](./yourproject/with_guice.mdx)。

## 为什么使用它？

过去关系型数据库占主导时，数据访问手段已趋多样并且涌现了大量基于 JDBC 的成熟工具；但随着 NoSQL 数据库兴起，数据存储形式更加多元访问 API 也变得更加复杂。
开发者需要在不同的 API 之间切换，增加了学习成本和使用难度。

而已有的数据访问技术如 Hibernate、MyBatis、Spring JDBC 等主要针对关系型数据库，在面对日益多样的非关系型存储时显现出局限性。

dbVisitor 的核心突破在于访问模式的无缝集成：开发者可以在同一项目中混合使用多种访问范式，并在关系型与非关系型存储之间获得统一体验。

在 API 设计上，dbVisitor 提供了与 Spring JdbcTemplate、MyBatis 近似风格的 API，这种设计可以让开发者避免接受大量新的概念和知识，从而减少学习成本和使用难度。

## 使用 dbVisitor

- dbVisitor 使用商业友好的 [Apache 2.0](https://www.apache.org/licenses/LICENSE-2.0.html) 许可协议。
- dbVisitor 核心模块只有 [Cobble](https://gitee.com/zycgit/cobble) 一个依赖（cobble 是一个类似 Apache Commons 或 Guava 的工具包）
- 已发布模块可通过 [Maven Central](https://central.sonatype.com/search?q=dbvisitor) 获取。

## 入门

- dbVisitor 支持通过 [编程式 API](./api/jdbc) 执行目标驱动支持的 SQL、DSL 或原生命令。
- dbVisitor 支持在接口上通过注解标记以 [声明式 API](./api/mapper) 方式来访问数据库。
- dbVisitor 支持通过 [构造器](./api/lambda) 用同一种 API 访问具备相应方言能力的数据源。
- dbVisitor 支持使用 [Map 查询模式](./core/map_query/about) 处理 Map 数据，可选择复用对象映射或直接使用表名、列名。
- dbVisitor 支持使用 [向量查询](./core/vector_query/about) 进行 KNN 排序和向量范围过滤。
- dbVisitor 支持通过 [Mapper API](./api/mapper) 用 Java 接口组织 DAO（含注解、BaseMapper 通用 CRUD、Mapper 文件）。
- dbVisitor 支持使用 [使用 Mapper XML](./api/file_mapper) 文件配置统一管理 SQL 语句。
- dbVisitor 提供多种方式处理 [参数传递](./args/about)，相信在各种特殊场景中总能找到一个适合的方式处理它们。
- dbVisitor 提供了一种更加灵活和高效的 [规则](./rules/about) 机制，通过规则可以更加简洁的维护应用程序 SQL。
- dbVisitor 内置多种 [类型处理器](./types/about)，可以方便的处理绝大多数数据库类型。
- dbVisitor 支持在多个不同方法调用之间使用 [数据库事务](./transaction/about)。
- dbVisitor 使用统一的 API 或一致编程风格访问 [Redis](../features/redis/about.md)、[MongoDB](../features/mongo/about.md)、[Elasticsearch](../features/elastic/about.md) 和 [Milvus](../features/milvus/about.md)。

## 框架整合

- [dbvisitor-spring](./yourproject/with_spring)，支持最低使用 [Spring 4.x](https://spring.io/projects/spring-framework) 及 [Spring Boot 2、Spring Boot 3](https://spring.io/projects/spring-boot) 中自动配置和注入 dbVisitor 配置的 Mapper 和实例。
- [dbvisitor-solon](./yourproject/with_solon)，支持在使用了 [Solon](https://solon.noear.org/) 作为应用程序开发框架的程序中自动配置和注入 dbVisitor 配置的 Mapper 和实例。
- [dbvisitor-hasor](./yourproject/with_hasor)，支持在使用了 [Hasor](https://www.hasor.net/) 作为应用程序开发框架的程序中自动配置和注入 dbVisitor 配置的 Mapper 和实例。
- [dbvisitor-guice](./yourproject/with_guice)，支持在使用了 [Google Guice](https://github.com/google/guice) 依赖注入的应用程序中自动配置和注入 dbVisitor 配置的 Mapper 和实例。
- [jdbc-redis](../drivers/redis/about) 是 Redis 的 JDBC 驱动适配器，它允许开发者使用标准的 JDBC 接口和 Redis 命令的方式来操作数据库。
- [jdbc-mongo](../drivers/mongo/about) 是 MongoDB 的 JDBC 驱动适配器，它允许开发者使用标准的 JDBC 接口和 MongoDB 命令的方式来操作数据库。
- [jdbc-elastic](../drivers/elastic/about) 是 ElasticSearch 的 JDBC 驱动适配器，它允许开发者使用标准的 JDBC 接口和 ElasticSearch QueryDSL 方式来操作数据。

- 最新正式版：v{Vars.lastReleaseVer}
