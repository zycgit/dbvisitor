## Dependencies and Versions

This page describes current `6.7.1-SNAPSHOT` source and requires Java 17+ to build and run. It is not a capability claim for older artifacts. For releases, use the actual POM, classifier and matching documentation.

Current source publishes an `all` classifier (relocated ANTLR, with other dependencies still transitive). Install locally from the repository root first:

```bash
./gradlew :dbvisitor-driver:publishToMavenLocal :jdbc-mongo:publishToMavenLocal
```

```xml
<dependency>
    <groupId>net.hasor</groupId>
    <artifactId>jdbc-mongo</artifactId>
    <version>6.7.1-SNAPSHOT</version>
    <classifier>all</classifier>
</dependency>
```

```groovy
repositories { mavenLocal(); mavenCentral() }
dependencies { implementation 'net.hasor:jdbc-mongo:6.7.1-SNAPSHOT:all' }
```

The local-install example does not assert that the SNAPSHOT is published on Maven Central.

## JDBC Connection
```java
String url = "jdbc:dbvisitor:mongo://127.0.0.1:27017/testdb?socketTimeout=5000";
Properties props = new Properties();
props.setProperty("user", "root");
props.setProperty("password", "123456");
props.setProperty("mechanism", "SCRAM-SHA-256");
Connection conn = DriverManager.getConnection(url, props);
```

JDBC URL format:
```
jdbc:dbvisitor:mongo://{host}:{port}/{database}?{param1=value1&param2=value2}
```

Cluster example (multiple hosts):
```
jdbc:dbvisitor:mongo://host1:27017;host2:27017/mydb
```

Parameters may be supplied in the URL or Properties; see [Connection Parameters](./params.md). The driver class is `net.hasor.dbvisitor.driver.JdbcDriver`. Fragments below assume an open `Connection conn` and imports `java.sql.*` and `java.util.*`; close the connection when finished.

Replace the example credentials and ensure the account's authentication database matches the database in the URL. These examples create collections and modify sample data; run them in a test environment.

## Code Examples

### 1) Create collection (DDL)
```java
try (Statement stmt = conn.createStatement()) {
    stmt.execute("use mydb");
    stmt.executeUpdate("db.createCollection('capped_col', { capped: true, size: 1024, max: 100 })");
}
```

### 2) Insert and update (DML)
```java
try (Statement stmt = conn.createStatement()) {
    stmt.executeUpdate("db.mycol.insert({name:'zhangsan'})");
    stmt.executeUpdate("db.mycol.update({name:'zhangsan'}, {$set:{age:20}})");
}
```

Here `db.mycol` uses the current database. To target another database, use `mydb1.mycol.insert(...)` and keep subsequent reads or updates in the same database.

### 3) Find with `ObjectId(?)` (DQL)
```java
try (PreparedStatement ps = conn.prepareStatement("db.complex_order.find({_id: ObjectId(?)})")) {
    ps.setString(1, "69399ba1c488515851cecdfb");
    try (ResultSet rs = ps.executeQuery()) {
        while (rs.next()) {
            rs.getString("_JSON");
        }
    }
}
```

### 4) Aggregate with options
```java
try (PreparedStatement ps = conn.prepareStatement(
        "db.mycol.aggregate([{$match: {}}], { allowDiskUse: ?, batchSize: ? })")) {
    ps.setBoolean(1, true);
    ps.setInt(2, 100);
    ps.executeQuery();
}
```

## Multiple Commands and JDBC Results

```java
try (Statement stmt = conn.createStatement()) {
    boolean hasResult = stmt.execute("db.mycol.find({}).limit(2); db.mycol.count({})");
    while (true) {
        if (hasResult) {
            try (ResultSet rs = stmt.getResultSet()) {
                while (rs.next()) System.out.println(rs.getObject(1));
            }
        } else {
            long count = stmt.getLargeUpdateCount();
            if (count == -1) break;
            System.out.println("updated=" + count);
        }
        hasResult = stmt.getMoreResults(Statement.CLOSE_CURRENT_RESULT);
    }
}
```

Use executeQuery for reads and executeUpdate or execute for writes. Semicolon-separated commands are consumed through execute/getMoreResults, not JDBC batch or a transaction. Hints go before the command; see [Command Reference](./commands.md) for all hints and limitations.
