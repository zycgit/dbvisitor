# Queries

JdbcTemplate offers APIs for reading result sets; method names do not force a connection or operation to be read-only. Most take an SQL string plus arguments (object or array) and return objects built from the result set; some provide callbacks/mappers for custom processing.

## Choose a Method First

| Goal | Method |
| --- | --- |
| Query multiple Bean or Map rows | `queryForList` |
| Query one Bean row | `queryForObject` |
| Query one Map row | `queryForMap` |
| Query a single value, such as count or sum | `queryForLong`, `queryForObject` |
| Query two columns as a Map | `queryForPairs` |
| Customize row mapping | `RowMapper` |
| Customize whole ResultSet handling | `ResultSetExtractor` |
| Process large results row by row | `RowCallbackHandler` or streaming query |

## Query Result Sets {#list}

Query a collection of objects or maps and return them.

<Tabs>
    <TabItem value="demo1" label="ObjectMapping">

        ```java
        // Raw SQL (independent example)
        {
            List<User> users = jdbc.queryForList(
                    "select * from users where id > 2", User.class);
        }

        // Positional arguments (independent example)
        {
            Object[] args = new Object[]{ 2 };
            List<User> result = jdbc.queryForList(
                    "select * from users where id > ?", args, User.class);
        }

        // Named arguments (independent example)
        {
            Map<String, Object> namedArgs = CollectionUtils.asMap("id", 2);
            List<User> result = jdbc.queryForList(
                    "select * from users where id > :id", namedArgs, User.class);
        }
        ```

    </TabItem>

## Query Key-Value Pairs {#pairs}

Use the first and second columns of the result set as Map key/value.

<Tabs>
    <TabItem value="demo" label="Example">

        ```java
        // Raw SQL (independent example)
        {
            Map<Long, String> userMap = jdbc.queryForPairs(
                    "select uid, name from user where age > 2", Long.class, String.class);
        }

        // Positional arguments (independent example)
        {
            Object[] args = new Object[]{ 2 };
            Map<Long, String> userMap = jdbc.queryForPairs(
                    "select uid, name from user where age > ?", Long.class, String.class, args);
        }

        // Named arguments (independent example)
        {
            Map<String, Object> namedArgs = CollectionUtils.asMap("age", 2);
            Map<Long, String> userMap = jdbc.queryForPairs(
                    "select uid, name from user where age > :age", Long.class, String.class, namedArgs);
        }
        ```

    </TabItem>
    <TabItem value="sig" label="Signatures">

        ```java
        // pairKey and pairValue use object mapping or type handlers.
        Map<K, V> queryForPairs(String sql,
                    Class<K> pairKey, Class<V> pairValue);
        Map<K, V> queryForPairs(String sql,
                    Class<K> pairKey, Class<V> pairValue, Object args);
        Map<K, V> queryForPairs(String sql,
                    Class<K> pairKey, Class<V> pairValue, PreparedStatementSetter args);
        ```

    </TabItem>
</Tabs>

## Query Values {#value}

Values are the smallest mappable units (types registered in [TypeHandlerRegistry](../../types/handlers/about)), e.g., `String`, `Int`, `Date`. Two common cases:
- Value lists, e.g., an ID collection.
- Aggregate info, e.g., counts or averages.

<Tabs>
    <TabItem value="demo1" label="Single value">

        ```java
        // Raw SQL (independent example)
        {
            long count = jdbc.queryForLong(
                    "select count(*) from user where age > 2");
        }

        // Positional arguments (independent example)
        {
            Object[] args = new Object[]{ 2 };
            long count = jdbc.queryForLong(
                    "select count(*) from user where age > ?", args);
        }

        // Named arguments (independent example)
        {
            Map<String, Object> namedArgs = CollectionUtils.asMap("age", 2);
            long count = jdbc.queryForLong(
                    "select count(*) from user where age > :age", namedArgs);
        }
        ```

        :::info[Hint]
        - `jdbc.queryForObject("select count(*) from users", Integer.class);` is equivalent.
        :::

    </TabItem>
    <TabItem value="demo2" label="Multiple value">

        ```java
        // Raw SQL (independent example)
        {
            List<String> result = jdbc.queryForList(
                    "select name from users", String.class);
        ```

## Result Receiving {#result}

These examples cover the most common return shapes. For more control over result mapping, choose from the following table; see [Receiving Results](../../result/about) for details.

| Goal | Use | Details |
| --- | --- | --- |
| Convert each row to an object | `RowMapper` | [RowMapper](../../result/for_mapper) |
| Receive column names and values without an entity class | `List<Map<String,Object>>` | [List/Map](../../result/for_map) |
| Consume large results row by row without collecting in memory | `RowCallbackHandler` | [RowCallbackHandler](../../result/row_callback) |
| Control the whole `ResultSet` traversal yourself | `ResultSetExtractor` | [ResultSetExtractor](../../result/for_extractor) |
| Serialize or deserialize single-column values | `TypeHandler` | [Type Handling](../../types/about) |

### Use ResultSetExtractor {#extractor}

```java
User user = jdbc.query(
    "select * from users where id = ?",
    new Object[]{ 1 },
    (ResultSetExtractor<User>) rs -> {
        if (!rs.next()) {
            return null;
        }

        User u = new User();
        u.setId(rs.getLong("id"));
        u.setName(rs.getString("name"));
        return u;
    }
);
```

### Row-by-Row Processing {#stream}

Callbacks avoid collecting all results in application memory. On-demand server reads still depend on the JDBC driver, fetchSize and connection settings.

```java
RowCallbackHandler handler = (rs, rowNum) -> {
    // Process each row without collecting a List
};

jdbc.query("select * from users where age > ?", new Object[]{ 18 }, handler);
```

### Map Case Sensitivity {#case}

By default, Map result keys are case-insensitive. Different databases may return column names with different casing, such as uppercase in Oracle or lowercase in MySQL. If you need strict case-sensitive keys, see [List/Map](../../result/for_map).

## Query Argument Notes {#arguments}

In query-related APIs, arguments are passed uniformly as `Object`. Supported types include:

- [Positional arguments](../../args/position) (put multiple values in an array or collection; the method takes `Object args`, not varargs)
    - Arrays, Collection, types registered in TypeRegistry
- [Named arguments](../../args/named)
    - Map, entity Bean, SqlArg (name will be fixed as `arg0`)
- Custom: fully custom argument-setting logic for scenarios requiring manual type control.
    - [PreparedStatementSetter](../../args/interface#pset), [SqlArgSource](../../args/interface#source)
- Dynamic SQL
    - Use [Rules](../../rules/dynamic_rule) to bind arguments when building query commands, supporting named arguments.
    - Using `${...}` for [SQL text substitution](../../args/inject) does not participate in PreparedStatement but is still a form of argument passing.


Argument types are ultimately processed through TypeHandler to ensure correct mapping between JDBC types and Java types.
