# Data Reads and Writes

dbVisitor executes SQL commands supported by JDBC-Milvus. Fluent and Mapper APIs are available, but they do not add relational features such as JOIN or transactions. Connection setup: [JDBC Milvus](../../../drivers/milvus/connection.mdx).

## Prepare and Load the Collection

Before running the examples, create the collection and index in an empty environment:

```sql
CREATE TABLE book_vectors (
    book_id INT64 PRIMARY KEY,
    title VARCHAR(256),
    word_count INT32,
    book_intro FLOAT_VECTOR(2)
) WITH (consistency_level='Strong');
CREATE INDEX idx_intro ON book_vectors (book_intro)
USING "AUTOINDEX" WITH (metric_type="L2");
LOAD TABLE book_vectors;
```

Load the collection before querying. Strong consistency helps read-after-write; iterator queries require this setting on the collection, not just the connection.

## Entity Mapping

FLOAT_VECTOR fields accept `List<Float>` directly; the list length must match the field dimension. See [Type Support](types.md) for other vector types.

```java
@Table("book_vectors")
public class BookVector {
    @Column(value = "book_id", primary = true)
    private Long bookId;
    private String title;
    @Column("word_count")
    private Integer wordCount;
    @Column("book_intro")
    private List<Float> bookIntro;
    // Getters and setters omitted
}
```

Keys are assigned by the application or generated by collection AutoID; see [Key Generation](generated-keys.mdx). Multiple writes are not a transaction; successful pages are not rolled back after a failure.

## Execute Commands {#exec-command}

Use a JdbcTemplate backed by the datasource:

```java
JdbcTemplate jdbc = new JdbcTemplate(dataSource);

jdbc.executeUpdate(
        "INSERT INTO book_vectors (book_id, title, word_count, book_intro) VALUES (?, ?, ?, ?)",
        new Object[] { 1001L, "mali", 100, List.of(0.1f, 0.2f) });

List<BookVector> rows = jdbc.queryForList(
        "SELECT * FROM book_vectors WHERE book_id = ?",
        new Object[] { 1001L }, BookVector.class);

jdbc.executeUpdate(
        "UPDATE book_vectors SET title = ? WHERE book_id = ?",
        new Object[] { "new title", 1001L });

jdbc.executeUpdate(
        "DELETE FROM book_vectors WHERE book_id = ?",
        new Object[] { 1001L });
```

## Vector Queries {#vector-query}

### Load the Collection and Match the Metric

Create an index and LOAD TABLE before searching. The query metric must match the index metric_type; an L2 index cannot serve a COSINE request.

```java
LambdaTemplate lambda = new LambdaTemplate(dataSource);
List<Float> target = List.of(0.1f, 0.2f);
List<BookVector> rows = lambda.query(BookVector.class)
        .gt(BookVector::getWordCount, 500)
        .orderByL2(BookVector::getBookIntro, target)
        .initPage(5, 0)
        .queryForList();
```

This sends a Search request with a scalar filter and takes five nearest candidates. Each ORDER BY accepts one query vector, not a list of multiple query vectors.

### Cosine and Inner-Product Thresholds

Milvus COSINE and IP return similarity scores: larger is better. To require a score above 0.8, use >, not a negative threshold or 1 - 0.8:

```java
List<BookVector> rows = jdbc.queryForList(
        "SELECT * FROM book_vectors WHERE book_intro <=> ? > ? LIMIT 10",
        new Object[] { target, 0.8 }, BookVector.class);
```

Run this on a collection indexed with COSINE; for IP use `<#>` and an IP index. The Fluent range methods currently generate `<`, so use this parameterized command for COSINE/IP ranges. vectorByL2 uses the correct smaller-than distance comparison.

Only one vector range may be combined with scalar filters through AND. Do not combine it with OR, NOT, another vector range, or vector ORDER BY.

### Multiple Search Paths

A scalar filter plus one vector search is not hybrid search. To merge multiple candidate lists, use HYBRID and choose the reranker in the command:

- [HYBRID and reranking](../query/hybrid.md)
- [BM25 and functions](../ddl/functions.md)
- [Search limits and returned columns](../query/select.md)

Common Fluent API usage is described in [Vector Query](../../../guides/core/vector_query/about.md).

## Failure During Multiple Updates

UPDATE without LIMIT does not stop at a fixed record count, but runs in pages. Successful pages are not rolled back after a failure; errors include confirmed progress. See [UPDATE and DELETE](../write/update.md) for recovery and retry scope.

See [Result Reading](../../../drivers/milvus/results.md) for returned columns. Multiple commands do not form a JDBC batch or transaction.

## Map Reads and Writes

| Entry point | Key names |
| --- | --- |
| Entity-based asMap() | Java property names |
| insertFreedom / queryFreedom | Milvus field names |
| BaseMapper Map methods | Registered entity property names |

updateByMap ignores NULL and omitted properties. replaceByMap replaces all updatable mapped properties: omitted values can become NULL. Supply values that must be retained and ensure cleared fields allow NULL.

BaseMapper upsertByMap queries before inserting or replacing; it is not the SQL UPSERT operation and is not atomic. JdbcTemplate.executeBatch executes statements individually with this driver; it does not use JDBC Batch.

## Fluent Write Differences

onDuplicateStrategy(Update) uses partial upsert and requires the primary key in the submitted data. New keys insert; existing keys update only submitted fields. Ignore is unsupported.

The Fluent API rejects UPDATE/DELETE without conditions unless allowEmptyWhere() is explicitly enabled. Plain SQL has no such protection. Do not prepend WHERE 1=1 when combining conditions on Milvus 2.6.2; use conditional API branches instead. Parameterized LIKE and NOT restrictions are described under [Operators](../basics/operators.md).

For Session and Mapper setup, see the core [Mapper API](../../../guides/core/mapper/about.md). Milvus-specific vector filtering is described above.
