# dbVisitor API Usage

dbVisitor accesses the Milvus vector database via the [JDBC-Milvus](../../drivers/milvus/about) driver, based on the JDBC protocol.
Unlike the native command style of MongoDB/ElasticSearch, the Milvus adapter uses **SQL-style syntax** (`CREATE TABLE`, `INSERT`, `SELECT`, `DELETE`, etc.), resulting in a lower learning curve.

This page shows how dbVisitor APIs execute the adapter's SQL subset. See [Installation and Connection](../../drivers/milvus/connection.mdx) for dependencies and connections, [Connection Parameters](../../drivers/milvus/params.md) for TLS, and [JDBC Operations](./jdbc.mdx) for a complete program. See [Supported Scope](./compatibility.md) for version requirements and feature boundaries. Examples use two-dimensional FloatVector fields; the application supplies dataSource, connection, entity accessors and Session.

**Supported capabilities:**

- Operate data using SQL-style commands ([supported command list](./commands))
- [JdbcTemplate](#exec-command), [Builder API](#exec-lambda), [BaseMapper](#exec-mapper), [Method Annotations](#exec-annotation), [Mapper File](#exec-file)
- Object mapping, result set mapping, [rules](../../guides/rules/about), [parameter passing](../../guides/args/about), [ResultSetExtractor/RowMapper](../../guides/result/about)
- **Vector Search**: KNN nearest neighbor search (`ORDER BY field <-> vector`), range search (`vector_range()`)

**Unsupported:** transactions/savepoints, JDBC executeBatch, stored procedures and updatable ResultSets. INSERT/UPSERT supports multiple VALUES, lazy Iterable/Iterator inputs and [JDBC generated keys](./jdbc.mdx#typed-values); these are not JDBC batch.

## Concept Analogy

The Milvus adapter uses JDBC calls but accepts only the SQL subset defined in the syntax manual:

- **DDL** — `CREATE TABLE`, `DROP TABLE`, `CREATE INDEX`, etc., executed via `executeUpdate`
- **DML** — `INSERT`, `UPDATE`, `DELETE`, obtain affected row count via `executeUpdate`
- **DQL** — `SELECT` queries return standard `ResultSet`, column names map one-to-one with collection fields

:::info[Milvus Special Requirements]
Milvus requires collections to be **loaded into memory** before querying; first execute `LOAD TABLE table_name`.
UPDATE selects keys in pages and submits only SET fields through native Partial Upsert. No fixed total is imposed without LIMIT, but pages are not transactional; confirmed pages are not rolled back and a failed page may have taken effect.
:::

## Command Mode (JdbcTemplate) {#exec-command}

Use JdbcTemplate to execute SQL-style commands to operate Milvus. Make sure the Milvus data source is properly configured first — see [Milvus Driver Usage Guide](./jdbc).

:::tip[Tip]
For more usage patterns, see the [JdbcTemplate class](../../guides/core/jdbc/about#guide). The following two features are unavailable due to driver limitations:
- JDBC addBatch/executeBatch (use the driver's multi-row write syntax instead)
- Stored procedures
:::

```java title='Create JdbcTemplate'
JdbcTemplate jdbc = new JdbcTemplate(dataSource);
// or
JdbcTemplate jdbc = new JdbcTemplate(connection);
```

```java title='Create collection and index'
// Create collection
jdbc.execute("CREATE TABLE book_vectors ("
    + "book_id INT64 PRIMARY KEY, "
    + "title VARCHAR(256) NOT NULL, "
    + "word_count INT32 DEFAULT 0, "
    + "book_intro FLOAT_VECTOR(2)"
    + ")");

// Create vector index
jdbc.execute("CREATE INDEX idx_intro ON book_vectors (book_intro) "
    + "USING \"IVF_FLAT\" WITH (nlist = 1024, metric_type = \"L2\")");

// Load collection into memory (must execute before searching)
jdbc.execute("LOAD TABLE book_vectors");
```

```java title='Insert data'
// Direct insert
jdbc.execute("INSERT INTO book_vectors (book_id, title, word_count, book_intro) "
    + "VALUES (1, 'Thinking in Java', 1000, [0.1, 0.2])");
// Parameterized insert (recommended)
jdbc.execute("INSERT INTO book_vectors (book_id, title, word_count, book_intro) "
    + "VALUES (?, ?, ?, ?)",
    new Object[] { 2L, "Design Patterns", 500, Arrays.asList(0.3f, 0.4f) });
```

```java title='Scalar conditional query'
List<Map<String, Object>> list = jdbc.queryForList(
    "SELECT * FROM book_vectors WHERE word_count > 500 LIMIT 10");

Map<String, Object> book = jdbc.queryForMap(
    "SELECT * FROM book_vectors WHERE book_id = 1");
```

```java title='Vector search (KNN)'
// Use <-> operator + ORDER BY + LIMIT for TopK nearest neighbor search
List<Map<String, Object>> results = jdbc.queryForList(
    "SELECT book_id, title FROM book_vectors "
    + "ORDER BY book_intro <-> ? LIMIT 5",
    new Object[] { Arrays.asList(0.1f, 0.2f) });
```

```java title='Vector range search'
// Approach 1: vector_range function (recommended)
List<Map<String, Object>> results = jdbc.queryForList(
    "SELECT * FROM book_vectors WHERE vector_range(book_intro, ?, 0.8)",
    new Object[] { Arrays.asList(0.1f, 0.2f) });

// Approach 2: comparison expression
List<Map<String, Object>> results = jdbc.queryForList(
    "SELECT * FROM book_vectors WHERE book_intro <-> ? < 0.8",
    new Object[] { Arrays.asList(0.1f, 0.2f) });
```

### Filtered Vector Search {#hybrid-query}

This is a single filtered search path. Use [native HYBRID syntax](./commands.md#hybrid) for multiple candidate paths and fused ranking.

```java title='Scalar filter + vector search'
List<Map<String, Object>> results = jdbc.queryForList(
    "SELECT book_id, title FROM book_vectors "
    + "WHERE word_count > 500 "
    + "ORDER BY book_intro <-> ? LIMIT 3",
    new Object[] { Arrays.asList(0.1f, 0.2f) });
```

```java title='Update and delete'
// Update by primary key
jdbc.execute("UPDATE book_vectors SET word_count = 1200 WHERE book_id = 1");
// Delete by primary key
jdbc.execute("DELETE FROM book_vectors WHERE book_id = 1");
```

## Builder API (LambdaTemplate) {#exec-lambda}

The Builder API provides a type-safe, fluent way to operate Milvus subject to the Milvus SQL subset. Do not use JOINs, scalar ordering, column aliases or cross-database qualified names. For details, see [Builder API](../../guides/core/lambda/about).

```java title='Initialize'
LambdaTemplate lambda = new LambdaTemplate(dataSource);
```

```java title='Insert'
BookVector book = new BookVector();
book.setBookId(1L);
book.setTitle("Thinking in Java");
book.setWordCount(1000);
book.setBookIntro(Arrays.asList(0.1f, 0.2f));

int result = lambda.insert(BookVector.class)
                   .applyEntity(book)
                   .executeSumResult();
```

```java title='Query'
BookVector book = lambda.query(BookVector.class)
                       .eq(BookVector::getBookId, 1L)
                       .queryForObject();

List<BookVector> books = lambda.query(BookVector.class)
                              .gt(BookVector::getWordCount, 500)
                              .queryForList();
```

```java title='Update'
int result = lambda.update(BookVector.class)
                   .eq(BookVector::getBookId, 1L)
                   .updateTo(BookVector::getWordCount, 1200)
                   .doUpdate();
```

```java title='Delete'
int result = lambda.delete(BookVector.class)
                   .eq(BookVector::getBookId, 1L)
                   .doDelete();
```

### Paginated Queries

```java title='Paginated query'
PageObject pageInfo = new PageObject(0, 10); // Page 0, 10 per page

List<BookVector> page1 = lambda.query(BookVector.class)
                               .gt(BookVector::getWordCount, 0)
                               .usePage(pageInfo)
                               .queryForList();

pageInfo.nextPage();
List<BookVector> page2 = lambda.query(BookVector.class)
                               .gt(BookVector::getWordCount, 0)
                               .usePage(pageInfo)
                               .queryForList();
```

## BaseMapper Interface {#exec-mapper}

`BaseMapper` provides CRUD entry points, but generated SQL, transactions and batching remain subject to adapter limitations. For details, see [BaseMapper](../../guides/core/mapper/about).

```java title='Define object'
@Table("book_vectors")
public class BookVector {
    @Column(value = "book_id", primary = true)
    private Long bookId;
    @Column("title")
    private String title;
    @Column("word_count")
    private Integer wordCount;
    @Column("book_intro")
    private List<Float> bookIntro;
    ... // getter/setter omitted
}
```

```java title='Define Mapper interface'
@SimpleMapper
public interface BookVectorMapper extends BaseMapper<BookVector> {
}
```

```java title='CRUD with Mapper'
Session session = ...;
BookVectorMapper mapper = session.createMapper(BookVectorMapper.class);

// Insert
mapper.insert(book);
// Query
BookVector loaded = mapper.selectById(1L);
// Update
loaded.setWordCount(1200);
mapper.update(loaded);
// Delete
mapper.deleteById(1L);
```

## Annotation Mode {#exec-annotation}

:::tip[Tip]
[Core API annotations](../../guides/core/mapper/about) can execute supported Milvus commands, such as @Insert/@Query/@Delete below. @Call is unsupported; annotations do not extend the driver's SQL or transaction capabilities.
Milvus uses SQL-style syntax, so command syntax in annotations is very close to traditional SQL.
:::

```java title='1. Define object'
@Table("book_vectors")
public class BookVector {
    @Column(value = "book_id", primary = true)
    private Long bookId;
    @Column("title")
    private String title;
    @Column("word_count")
    private Integer wordCount;
    @Column("book_intro")
    private List<Float> bookIntro;
    ... // getter/setter omitted
}
```

```java title='2. Define Mapper interface'
@SimpleMapper
public interface BookVectorMapper {
    @Insert("INSERT INTO book_vectors (book_id, title, word_count, book_intro) "
          + "VALUES (#{bookId}, #{title}, #{wordCount}, #{bookIntro})")
    int saveBook(BookVector book);

    @Query("SELECT * FROM book_vectors WHERE book_id = #{bookId}")
    BookVector loadBook(@Param("bookId") Long bookId);

    @Delete("DELETE FROM book_vectors WHERE book_id = #{bookId}")
    int deleteBook(@Param("bookId") Long bookId);
}
```

```java title='3. Create and use Mapper'
Configuration config = new Configuration();
Session session = config.newSession(dataSource);

BookVectorMapper mapper = session.createMapper(BookVectorMapper.class);
```

### Consistency Level {#consistency}

:::info[Consistency Level]
Milvus's default consistency level may prevent newly inserted data from being immediately queryable. It is recommended to add `consistencyLevel=Strong` to the JDBC connection URL to ensure immediate visibility:

```text
jdbc:dbvisitor:milvus://host:port?consistencyLevel=Strong
```
:::

### Paginated Queries

Add a `Page` parameter to Mapper methods for paginated queries.

```java title='Mapper definition'
@SimpleMapper
public interface BookVectorMapper {
    @Query("SELECT * FROM book_vectors WHERE word_count > 0")
    List<BookVector> queryAll(Page page);
}
```

```java title='Paginated call'
Page page = new PageObject();
page.setPageSize(10);

List<BookVector> list = mapper.queryAll(page);
```

```xml title='2. Define Mapper file'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//dbvisitor.net//DTD Mapper 1.0//EN"
"https://www.dbvisitor.net/schema/dbvisitor-mapper.dtd">
<mapper namespace="com.example.mapper.BookVectorMapper">
    <resultMap id="bookResultMap" type="com.example.dto.BookVector">
        <id property="bookId" column="book_id"/>
        <result property="title" column="title"/>
        <result property="wordCount" column="word_count"/>
        <result property="bookIntro" column="book_intro"/>
    </resultMap>

    <insert id="saveBook">
        INSERT INTO book_vectors (book_id, title, word_count, book_intro)
        VALUES (#{bookId}, #{title}, #{wordCount}, #{bookIntro})
    </insert>

    <select id="loadBook" resultMap="bookResultMap">
        SELECT * FROM book_vectors WHERE book_id = #{bookId}
    </select>

    <select id="queryAll" resultMap="bookResultMap">
        SELECT * FROM book_vectors LIMIT 100
    </select>

    <delete id="deleteBook">
        DELETE FROM book_vectors WHERE book_id = #{bookId}
    </delete>
</mapper>
```

```java title='3. Define Mapper interface'
@RefMapper("/mapper/book-vector-mapper.xml")
public interface BookVectorMapper {
    int saveBook(BookVector book);

    BookVector loadBook(@Param("bookId") Long bookId);

    List<BookVector> queryAll();

    int deleteBook(@Param("bookId") Long bookId);
}
```

## Vector Search {#vector-search}

Milvus's core capability is vector similarity retrieval. dbVisitor's Builder API provides type-safe vector search methods without requiring hand-written SQL — recommended for primary use.
For complete vector query documentation, see [Vector Queries](../../guides/core/vector_query/about).

### KNN Nearest Neighbor Search (orderBy*)

The query metric must match the index metric_type. The index above uses L2; before trying COSINE/IP examples, create a separate collection and index with that metric.

Use `orderByL2` / `orderByCosine` / `orderByIP` to sort by vector similarity, combined with `initPage` to get the top K most similar records:

```java title='L2 distance TopK search'
LambdaTemplate lambda = new LambdaTemplate(dataSource);
List<Float> target = Arrays.asList(0.1f, 0.2f);

List<BookVector> results = lambda.query(BookVector.class)
        .orderByL2(BookVector::getBookIntro, target)
        .initPage(10, 0)  // TopK = 10
        .queryForList();
```

```java title='KNN search with scalar pre-filtering'
List<BookVector> results = lambda.query(BookVector.class)
        .gt(BookVector::getWordCount, 500)
        .orderByL2(BookVector::getBookIntro, target)
        .initPage(5, 0)
        .queryForList();
```

```java title='Cosine distance search'
List<BookVector> results = lambda.query(BookVector.class)
        .orderByCosine(BookVector::getBookIntro, target)
        .initPage(10, 0)
        .queryForList();
```

### Range Search (vectorBy*)

`vectorByL2` means L2 distance below the threshold. Only one vector range combined with scalar predicates using AND is supported, not vector ranges under OR/NOT, multiple ranges or simultaneous ORDER BY. The current MilvusDialect range builder always emits `<`, so `vectorByCosine` / `vectorByIP` cannot express the required similarity range here. Use prepared SQL `field <=> ? > ?` / `field <#> ? > ?` instead.

```java title='L2 distance range filter'
List<Float> target = Arrays.asList(0.1f, 0.2f);

List<BookVector> results = lambda.query(BookVector.class)
        .vectorByL2(BookVector::getBookIntro, target, 0.8)
        .queryForList();
```

```java title='Hybrid condition: range search + scalar filter'
List<BookVector> results = lambda.query(BookVector.class)
        .vectorByL2(BookVector::getBookIntro, target, 0.8)
        .gt(BookVector::getWordCount, 500)
        .queryForList();
```

### API Quick Reference

| Query Mode | Method | Description |
|---------|------|------|
| KNN Sort | `orderByL2(property, vector)` | Sort by L2 Euclidean distance |
| KNN Sort | `orderByCosine(property, vector)` | Sort by cosine distance |
| KNN Sort | `orderByIP(property, vector)` | Sort by inner product distance |
| KNN Sort | `orderByMetric(MetricType, property, vector)` | Generic metric interface |
| Range Filter | `vectorByL2(property, vector, threshold)` | L2 distance < threshold |
| COSINE Range | Prepared SQL: `field <=> ? > ?` | Similarity above threshold |
| IP Range | Prepared SQL: `field <#> ? > ?` | Inner product above threshold |

:::tip[SQL Command Mode]
To use SQL-style syntax directly for vector search (e.g., `ORDER BY field <-> vector`, `vector_range()`, etc.), see the [supported command list](./commands#dql).
:::
