# Data Reads and Writes

dbVisitor treats `HTTP method + path + JSON` as an executable statement. `@Query` accepts REST commands, not just SELECT. These examples use Elasticsearch 7 typeless requests. Connection setup: [JDBC Elasticsearch](../../../drivers/elastic/connection.mdx).

## Entity Mapping

```java
@Table("user_info")
public class UserInfo {
    @Column(primary = true)
    private String uid;
    private String name;
    // Getters and setters omitted
}
```

`uid` is a document field, not Elasticsearch `_id`. `primary=true` neither creates a unique constraint nor uses uid as the document ID. Duplicate uid values can cause multiple documents to be updated or deleted. See [Key Generation](generated-keys.mdx).

## Execute Commands {#exec-command}

Use a JdbcTemplate backed by the datasource:

```java
JdbcTemplate jdbc = new JdbcTemplate(dataSource);

jdbc.executeUpdate(
        "POST /user_info/_doc?refresh=wait_for {\"uid\": ?, \"name\": ?}",
        new Object[] { "1001", "mali" });

List<UserInfo> rows = jdbc.queryForList(
        "POST /user_info/_search {\"query\":{\"term\":{\"uid\": ?}}}",
        new Object[] { "1001" }, UserInfo.class);

jdbc.executeUpdate(
        "POST /user_info/_update_by_query?refresh=true {\"query\":{\"term\":{\"uid\": ?}},\"script\":{\"source\":\"ctx._source.name = params.name\",\"params\":{\"name\": ?}}}",
        new Object[] { "1001", "new name" });

jdbc.executeUpdate(
        "POST /user_info/_delete_by_query?refresh=true {\"query\":{\"term\":{\"uid\": ?}}}",
        new Object[] { "1001" });
```

## Query Through Different APIs

<Tabs>
<TabItem value="fluent" label="Fluent API" default>

```java
LambdaTemplate lambda = new LambdaTemplate(dataSource);
UserInfo item = lambda.query(UserInfo.class)
        .eq(UserInfo::getUid, "1001")
        .queryForObject();
```

Fluent operations produce these database actions:

| Operation | Database action |
| --- | --- |
| Query | _search |
| Update selected properties | _update_by_query |
| Delete matching records | _delete_by_query |

BaseMapper CRUD uses the same operations.

</TabItem>
<TabItem value="annotation" label="Method Annotations">

```java
@SimpleMapper
public interface UserInfoMapper {
    @Query("POST /user_info/_search {\"query\":{\"term\":{\"uid\": #{uid}}}}")
    UserInfo findById(@Param("uid") String uid);
}
```

```java
Session session = new Configuration().newSession(dataSource);
UserInfoMapper mapper = session.createMapper(UserInfoMapper.class);
UserInfo item = mapper.findById("1001");
```

</TabItem>
<TabItem value="xml" label="Mapper File">

```xml
<mapper namespace="com.example.UserInfoMapper">
    <select id="findById" resultType="com.example.UserInfo">

```

```java
@RefMapper("/mapper/elastic-user.xml")
public interface UserInfoMapper {
    UserInfo findById(@Param("uid") String uid);
}
```

Save the XML as the resource named in @RefMapper; the example classes use package com.example. Create the Mapper through Session as in the annotation example.

## Exact Matching and Read-After-Write

Create the index with uid and name mapped as keyword before running the examples:

```text
PUT /user_info {"mappings":{"properties":{"uid":{"type":"keyword"},"name":{"type":"keyword"}}}}
```

Fluent `eq` produces a match query. On a text field, it can match analyzed terms. For exact matching, use a keyword field and the term request above.

For immediate search visibility after a single-document write, use `refresh=wait_for`. For Fluent API write-then-query calls, configure `indexRefresh=true` on the connection, at the cost of more frequent index refreshes.

See [Result Reading](results.mdx) for returned columns. Multiple commands do not form a JDBC batch or transaction.
