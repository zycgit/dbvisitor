# Pagination

Elasticsearch uses `from` and `size` for search pages and `_count` for totals. These requests fetch page two with ten records:
```text
POST /user_info/_search {"query":{"match_all":{}},"sort":[{"uid":"asc"}],"from":10,"size":10}
POST /user_info/_count {"query":{"match_all":{}}}
```
Map `uid` as keyword and ensure unique values in the application.

## dbVisitor Usage

Add a Page argument to a Mapper method. The entity mapping is shown in [Data Reads and Writes](usage.mdx).

```java
@Query("""
        POST /user_info/_search
        {"query":{"match_all":{}},"sort":[{"uid":"asc"}]}
        """)
List<UserInfo> findPage(Page page);
```

```java
Page page = new PageObject(1, 10);
List<UserInfo> rows = mapper.findPage(page);
```

Page numbering starts at zero. Page overrides from/size on search requests and uses `_count` when a total is required. This pages search hits, not aggregation buckets.

## Notes

Deep pages are subject to the server result window. The driver does not switch to search_after or scroll. `queryForList` reads only this response, not the entire index.

Counts and page reads are separate requests; concurrent writes can change their results. See [9.5 Pagination](../../../guides/result/page_object.mdx) for the common API.
