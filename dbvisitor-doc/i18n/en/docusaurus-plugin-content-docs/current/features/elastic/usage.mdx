# dbVisitor API Usage

dbVisitor accesses ElasticSearch data sources via the [JDBC-Elastic](../../drivers/elastic/about) driver, based on the JDBC protocol.

**Supported capabilities:**
- Operate data using ElasticSearch DSL commands ([supported command list](./commands))
- [JdbcTemplate](#exec-command), [Builder API](#exec-lambda), [BaseMapper](#exec-mapper), [Method Annotations](#exec-annotation), [Mapper File](#exec-file)
- Object mapping, result set mapping, [rules](../../guides/rules/about), [parameter passing](../../guides/args/about), [ResultSetExtractor/RowMapper](../../guides/result/about)
- [Dynamic SQL](../../guides/core/file/dynamic_sql) tags in Mapper File, `Statement.RETURN_GENERATED_KEYS` (auto-retrieve `_id`)

**Not supported:** JDBC addBatch/executeBatch, transactions, stored procedures

## Concept Analogy

Execution results of different ElasticSearch commands fall into two categories:
- **Update count** — analogous to INSERT/UPDATE/DELETE, obtained via `executeUpdate`
- **Single/Multi-row results** — analogous to SELECT result sets, document queries normally include `_ID`, `_DOC` (strings), and document fields. See the driver reference for administrative and aggregate results

## Command Mode (JdbcTemplate) {#exec-command}

Use JdbcTemplate to execute ElasticSearch commands directly. Make sure the ElasticSearch data source is properly configured first — see [ElasticSearch Driver Usage Guide](./jdbc).

:::tip[Tip]
For more usage patterns, see the [JdbcTemplate class](../../guides/core/jdbc/about#guide). The following two features are unavailable due to driver limitations:
- JDBC Batch (use supported multi-document commands instead)
- Stored procedures
:::

```java title='Create JdbcTemplate'
JdbcTemplate jdbc = new JdbcTemplate(dataSource);
// or
JdbcTemplate jdbc = new JdbcTemplate(connection);
```

```java title='Insert data'
// Direct command
jdbc.execute("POST /my_index/_doc/1 { \"name\": \"mali\", \"age\": 26 }");
// Parameterized command
jdbc.execute("POST /my_index/_doc/1 { \"name\": ?, \"age\": ? }", new Object[] { "mali", 26 });
```

```java title='Query data'
// First matching results; omitted size uses the Elasticsearch default
List<Map<String, Object>> list = jdbc.queryForList(
    "POST /my_index/_search { \"query\": { \"match_all\": {} } }");
// Conditional query
Map<String, Object> mali = jdbc.queryForMap(
    "POST /my_index/_search { \"query\": { \"term\": { \"name\": \"mali\" } } }");
String json = mali == null ? null : (String) mali.get("_DOC");
```

```java title='Update data'
jdbc.execute("POST /my_index/_update/1 { \"doc\": { \"age\": 27 } }");
```

```java title='Delete data'
jdbc.execute("DELETE /my_index/_doc/1");
```

---

Search visibility depends on refresh. Add `?refresh=wait_for` to writes when you need immediate search visibility. String fields used with exact `term` queries should be mapped as `keyword`.

## Generated IDs {#id-fill}

Use native JDBC `prepareStatement(command, Statement.RETURN_GENERATED_KEYS)`, then read `_id` through `getGeneratedKeys()`. For Mapper backfill into `info.id`, omit `keyColumn`:

```java
@Insert(value = "POST /user_info/_doc { \"name\": #{info.name} }", useGeneratedKeys = true, keyProperty = "info.id")
int insertWithId(@Param("info") UserWithId info);
```

`UserWithId` needs a writable `String id` property. This is JDBC/Mapper key retrieval. Lambda `KeyType.Auto` selects the unsupported column-name JDBC overload; assign business IDs yourself instead.

## Builder API (LambdaTemplate) {#exec-lambda}

The Builder API provides a type-safe, fluent way to operate ElasticSearch with the same usage as RDBMS. For details, see [Builder API](../../guides/core/lambda/about).

```java title='Initialize'
LambdaTemplate lambda = new LambdaTemplate(dataSource);
```

```java title='Insert'
UserInfo user = new UserInfo();
user.setUid("1001");
user.setName("test_user");

int result = lambda.insert(UserInfo.class)
                   .applyEntity(user)
                   .executeSumResult();
```

```java title='Query'
UserInfo user = lambda.query(UserInfo.class)
                      .eq(UserInfo::getUid, "1001")
                      .queryForObject();

List<UserInfo> users = lambda.query(UserInfo.class)
                             .like(UserInfo::getName, "test")
                             .queryForList();
```

```java title='Update'
int result = lambda.update(UserInfo.class)
                   .eq(UserInfo::getUid, "1001")
                   .updateTo(UserInfo::getName, "New Name")
                   .doUpdate();
```

```java title='Delete'
int result = lambda.delete(UserInfo.class)
                   .eq(UserInfo::getUid, "1001")
                   .doDelete();
```

## BaseMapper Interface {#exec-mapper}

`BaseMapper` provides generic CRUD methods with the same usage as RDBMS. For details, see [BaseMapper](../../guides/core/mapper/about).

```java title='Define Mapper interface'
@SimpleMapper
public interface UserInfoMapper extends BaseMapper<UserInfo> {
    // Custom methods can be added here
}
```

```java title='CRUD with Mapper'
Session session = ...;
UserInfoMapper mapper = session.createMapper(UserInfoMapper.class);

// Insert
mapper.insert(user);
// Query
UserInfo loadedUser = mapper.selectById(user.getUid());
// Update
loadedUser.setName("updated_name");
mapper.update(loadedUser);
// Delete
mapper.deleteById(user.getUid());
```

## Annotation Mode {#exec-annotation}

:::tip[Tip]
For the [Core API annotations](../../guides/core/mapper/about), all annotations work normally on ElasticSearch except `@Call`.
:::

```java title='1. Define object'
@Table("user_info")
public class UserInfo {
    @Column(value = "uid", primary = true)
    private String uid;
    @Column("name")
    private String name;
    ... // getter/setter omitted
}
```

```java title='2. Define Mapper interface'
@SimpleMapper()
public interface UserInfoMapper {
    @Insert("POST /user_info/_doc { \"uid\": #{info.uid}, \"name\": #{info.name} }")
    int saveUser(@Param("info") UserInfo info);

    @Query("POST /user_info/_search { \"query\": { \"term\": { \"uid\": #{uid} } } }")
    UserInfo loadUser(@Param("uid") String uid);

    @Delete("POST /user_info/_delete_by_query { \"query\": { \"term\": { \"uid\": #{uid} } } }")
    int deleteUser(@Param("uid") String uid);
}
```

```java title='3. Create and use Mapper'
Configuration config = new Configuration();
Session session = config.newSession(dataSource);

UserInfoMapper mapper = session.createMapper(UserInfoMapper.class);
```

### Paginated Queries {#pagination}

Add a `Page` parameter to Mapper methods for paginated queries.

```java title='Mapper definition'
@SimpleMapper()
public interface UserInfoMapper {
    @Query("POST /user_info/_search { \"query\": { \"match_all\": {} } }")
    List<UserInfo> queryAll(Page page);
}
```

```java title='Paginated call'
Page page = new PageObject();
page.setPageSize(10);

List<UserInfo> list = mapper.queryAll(page);
```

## File Mode (Mapper File) {#exec-file}

```java title='1. Define object'
@Table("user_info")
public class UserInfo {
    @Column(value = "uid", primary = true)
    private String uid;
    @Column("name")
    private String name;
    ... // getter/setter omitted
}
```

```xml title='2. Define Mapper file'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//dbvisitor.net//DTD Mapper 1.0//EN"
"https://www.dbvisitor.net/schema/dbvisitor-mapper.dtd">
<mapper namespace="net.test.dto.UserInfoMapper">
    <insert id="saveUser">
        POST /user_info/_doc {
            "uid": #{info.uid},
            "name": #{info.name}
        }
    </insert>

    <select id="loadUser" resultType="net.test.dto.UserInfo">
        POST /user_info/_search {
            "query": {
                "term": { "uid": #{uid} }
            }
        }
    </select>

    <delete id="deleteUser">
        POST /user_info/_delete_by_query {
            "query": {
                "term": { "uid": #{uid} }
            }
        }
    </delete>
</mapper>
```

```java title='3. Define Mapper interface'
@RefMapper("/path/to/mapper.xml")
public interface UserInfoMapper {
    int saveUser(@Param("info") UserInfo info);

    UserInfo loadUser(@Param("uid") String uid);

    int deleteUser(@Param("uid") String uid);
}
```
