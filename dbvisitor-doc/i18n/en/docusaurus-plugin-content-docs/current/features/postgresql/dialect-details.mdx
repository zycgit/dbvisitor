# PostgreSQL Dialect Details

## Pagination SQL

PostgreSQL dialect uses `LIMIT ? OFFSET ?` syntax:

```sql
-- offset=1, limit=3
SELECT ... LIMIT ? OFFSET ?
```

Parameter order: `LIMIT count OFFSET offset`.

## Count SQL

```sql
SELECT COUNT(*) FROM (original query) as TEMP_T
```

## Identifier Quoting

Uses double quotes `"`:

```sql
SELECT * FROM "users" WHERE "name" = ?
```

## LIKE Syntax

| LIKE Type | Generated SQL |
|-----------|-----------|
| Full fuzzy | `LIKE '%' || ? || '%'` |
| Left fuzzy | `LIKE '%' || ?` |
| Right fuzzy | `LIKE ? || '%'` |

Uses `||` string concatenation (instead of MySQL's `CONCAT`).

## Write Conflict Strategies

| Strategy | SQL Syntax | PK Required |
|------|---------|:----------:|
| Into | `INSERT INTO ... VALUES (...)` | No |
| Ignore | `INSERT INTO ... ON CONFLICT DO NOTHING` | No |
| Update | `INSERT INTO ... ON CONFLICT("pk") DO UPDATE SET ("col1","col2") = (EXCLUDED."col1", EXCLUDED."col2")` | Yes |

**Special limitation of Update strategy**: at least one non-primary key column must be updatable. If the table only has primary key columns (no other columns), the Update strategy is unavailable (returns `false`).

## Sequences

PostgreSQL dialect implements `SeqSqlDialect`, supporting `nextval()`:

```sql
SELECT NEXTVAL('user_info_id_seq')
```

Used in object mapping via `@KeySeq("user_info_id_seq")` + `KeyType.Sequence`.

## RETURNING Clause

PostgreSQL natively supports `INSERT ... RETURNING <column>`. Lambda/BaseMapper generates the following for multi-row inserts with primary key backfill:

```sql
INSERT INTO "user_info" ("name", "age")
VALUES (?, ?), (?, ?), (?, ?)
RETURNING "id"
```

With `ON CONFLICT DO UPDATE`, `RETURNING` can also be appended:

```sql
INSERT INTO "user_info" ("id", "name", "age") VALUES (?, ?, ?), (?, ?, ?)
ON CONFLICT ("id") DO UPDATE SET ("name", "age") = (EXCLUDED."name", EXCLUDED."age")
RETURNING "id"
```

Generated key columns are read from the current `ResultSet` (`MultiValuesResultSet`).

## Vector Search

PostgreSQL supports vector search via the pgvector extension, implementing `VectorSqlDialect`:

| Metric | Operator |
|---------|-------|
| L2 Euclidean distance | `<->` |
| Cosine distance | `<=>` |
| Inner product | `<#>` |

## Key Differences Summary

- `RETURNING` returns multiple primary keys (`MultiValuesResultSet`), the only database that can also use `RETURNING` with Update conflict strategy
- `ON CONFLICT DO NOTHING` does not require primary key columns
- `ON CONFLICT DO UPDATE` requires primary key columns and at least one non-primary key column
- String concatenation uses `||`, not `CONCAT`
- Supports sequences + vector search
