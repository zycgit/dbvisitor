# Key Generation

Generate a business ID before insertion and read it from the entity afterward. The example below uses `KeyType.UUID32`.

:::info[Note]
For general configuration, see [Generated Keys](../../guides/core/mapper/annotation_insert#generated-keys).
:::

## Using an Application-Side ID

```sql
CREATE TABLE event_log (id String, event_name String)
ENGINE = MergeTree ORDER BY id;
```

If the business requires a unique ID, generating it on the Java side is recommended — for example, UUID, Snowflake ID, or business numbers.

<Tabs>
<TabItem value="application-lambda" label="Fluent API" default>

```java title='ClickHouse application-side ID mapping'
@Table("event_log")
public class EventLog {
    @Column(value = "id", primary = true, keyType = KeyType.UUID32)
    private String id;

    @Column("event_name")
    private String eventName;
}
```

```java title='Lambda insert'
EventLog event = new EventLog();
event.setEventName("login");

LambdaTemplate lambda = ...;
lambda.insert(EventLog.class)
      .applyEntity(event)
      .executeSumResult();

String id = event.getId();
```

`KeyType.UUID32` / `KeyType.UUID36` generates IDs before insert and does not depend on ClickHouse returning generated keys.

</TabItem>
<TabItem value="application-annotation" label="Method Annotations">

```java
@Insert("INSERT INTO event_log (id, event_name) VALUES (#{id}, #{eventName})")
int insertEvent(EventLog event);
```


Assign the ID before calling the mapper:

```java
import java.util.UUID;

EventLog event = new EventLog();
event.setId(UUID.randomUUID().toString().replace("-", ""));
event.setEventName("login");
mapper.insertEvent(event);
```

</TabItem>
<TabItem value="application-xml" label="Mapper File">

Mapper SQL should explicitly write the application-generated ID:

```xml title='Recommended'
<insert id="insertEvent">
    INSERT INTO event_log (id, event_name)
    VALUES (#{id}, #{eventName})
</insert>
```

</TabItem>
</Tabs>
