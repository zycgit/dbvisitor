# Dameng Dialect Details

## Pagination SQL

Dameng uses `LIMIT` syntax (same as MySQL), omitting parameters when offset is 0:

```sql
-- offset=1, limit=3
SELECT ... LIMIT ?, ?

-- offset=0, limit=3
SELECT ... LIMIT ?
```

## Count SQL

```sql
SELECT COUNT(*) FROM (original query) as TEMP_T
```

## Identifier Quoting

Uses double quotes `"`:

```sql
SELECT * FROM "users" WHERE "name" = ?
```

## Write Conflict Strategies

| Strategy | SQL Syntax | PK Required |
|------|---------|:----------:|
| Into | `INSERT INTO ... VALUES (...)` | No |
| Ignore | `INSERT /*+ IGNORE_ROW_ON_DUPKEY_INDEX */ INTO ...` | Yes |
| Update | `MERGE INTO ... WHEN MATCHED THEN UPDATE ... WHEN NOT MATCHED THEN INSERT ...` | Yes, and at least one non-PK column |

**Dameng unique feature**: The Ignore strategy uses the database HINT `IGNORE_ROW_ON_DUPKEY_INDEX` instead of SQL Server/Oracle's `MERGE`. This is Dameng-specific syntax.

The Update strategy uses `MERGE` (highly consistent with Oracle syntax, also using `FROM dual`).

## Generated Key Strategy

| Scenario | GeneratedKeyStrategy |
|------|---------------------|
| No backfill columns | `JdbcBatch` |
| With backfill columns (any strategy) | `OneByOne` |

## Sequences

Dameng implements `SeqSqlDialect`:

```sql
SELECT user_seq.NEXTVAL
```

With schema:

```sql
SELECT "app"."user_seq".NEXTVAL
```

Used in object mapping via `@KeySeq("user_seq")` + `KeyType.Sequence`.

## Key Differences Summary

- Ignore strategy uses the unique `IGNORE_ROW_ON_DUPKEY_INDEX` HINT (not `MERGE`)
- Update strategy requires at least one non-primary key column to be updatable (unavailable for pure PK column lists)
- Pagination same as MySQL (`LIMIT ?, ?`)
- MERGE syntax consistent with Oracle (`FROM dual`)
- Supports sequences: `SELECT seq.NEXTVAL`
