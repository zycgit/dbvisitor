# SQL Server

SQL Server can use all of dbVisitor's general capabilities including JDBC, Mapper, Lambda, BaseMapper, transactions, functions, and procedures.

## Quick Overview of Differences

| Concern | SQL Server Behavior |
|--------|---------------|
| Primary Key Generation | `IDENTITY` or sequence default; recommend `OUTPUT INSERTED` for backfill |
| Pagination | `ROW_NUMBER() OVER(...)` with an outer range filter |
| Write Conflicts | `MERGE INTO ... WHEN MATCHED ... WHEN NOT MATCHED ...` |
| Batch Writes | JDBC batch supported |
| Stored Procedures | Supported |
| Sequences | The database supports `NEXT VALUE FOR seq`; the built-in dialect does not implement SeqSqlDialect |

## Primary Key Backfill

SQL Server recommends using `OUTPUT INSERTED.<column>` to return generated primary keys:

```sql
INSERT INTO user_info (name, age)
OUTPUT INSERTED.id
VALUES (?, ?)
```

INSERTs generated by Lambda / BaseMapper will automatically include `OUTPUT INSERTED` via the SQL Server dialect, backfilling primary keys from the current ResultSet. Hand-written SQL requires explicitly writing `OUTPUT INSERTED` and configuring `generatedKeySource="resultSet"`.

If not using `OUTPUT INSERTED`, you can also use JDBC generated keys (similar to MySQL).

## Caveats

- Duplicate column names cannot appear in `ORDER BY`
- `SELECT` statements using `LIMIT` syntax should be replaced with `TOP` or `OFFSET FETCH`
- Stored procedures, functions, and TVFs should use SQL Server-specific syntax

## Write Conflict Strategies

| Strategy | SQL Server Implementation |
|------|---------------|
| Ignore | `MERGE INTO ... WHEN NOT MATCHED THEN INSERT` (requires PK) |
| Update | `MERGE INTO ... WHEN MATCHED THEN UPDATE ... WHEN NOT MATCHED THEN INSERT` (requires PK) |
