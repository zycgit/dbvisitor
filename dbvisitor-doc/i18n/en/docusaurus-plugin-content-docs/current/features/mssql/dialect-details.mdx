# Dialect Details

## Pagination SQL

The SQL Server dialect uses `ROW_NUMBER()` + CTE. With offset=1 and limit=3, boundaries are inserted into SQL directly, not bound as new JDBC placeholders. Use a stable ORDER BY for repeatable pages:

```sql
WITH selectTemp AS (
  SELECT TOP 100 PERCENT ROW_NUMBER() OVER (ORDER BY CURRENT_TIMESTAMP) as __row_number__, *
  FROM original query
)
SELECT * FROM selectTemp
WHERE __row_number__ BETWEEN 2 AND 4
ORDER BY __row_number__
```

When the original query already has `ORDER BY`, the `ROW_NUMBER()` `OVER` clause reuses that ordering:

```sql
WITH selectTemp AS (
  SELECT TOP 100 PERCENT ROW_NUMBER() OVER (order by a desc) as __row_number__, *
  FROM original query (containing order by a desc)
)
SELECT * FROM selectTemp
WHERE __row_number__ BETWEEN 2 AND 4
ORDER BY __row_number__
```

## Count SQL

```sql
SELECT COUNT(*) FROM (original query) as TEMP_T
```

## Identifier Quoting

Uses square brackets `[]`:

```sql
SELECT * FROM [users] WHERE [name] = ?
```

**Important**: SQL Server's default schema is `dbo`. When only a catalog is specified without a schema, `dbo` is automatically inserted:

```
catalog.[table]  →  [catalog].dbo.[table]
schema.[table]   →  [schema].[table]
```

## Write Conflict Strategies

| Strategy | SQL Syntax | PK Required |
|------|---------|:----------:|
| Into | `INSERT INTO ... VALUES (...)` | No |
| Ignore | `MERGE INTO ... WHEN NOT MATCHED THEN INSERT ...` | Yes |
| Update | `MERGE INTO ... WHEN MATCHED THEN UPDATE ... WHEN NOT MATCHED THEN INSERT ...` | Yes |

## OUTPUT INSERTED

The SQL Server dialect generates `OUTPUT INSERTED` when primary key backfill is needed:

```sql
INSERT INTO [dbo].[user_info] ([name], [age])
OUTPUT INSERTED.[id]
VALUES (?, ?), (?, ?), (?, ?)
```

Multi-row inserts are read from the current `ResultSet` (`MultiValuesResultSet`), similar to PostgreSQL `RETURNING`.

For Ignore/Update + backfill columns, conservative `OneByOne` (row-by-row execution) is used.

## Sequences

The built-in SQL Server dialect does not implement `SeqSqlDialect`; do not directly use `@KeySeq` + `KeyType.Sequence`. Use `selectKey`, `@SelectKeySql`, or application code:

```sql
SELECT NEXT VALUE FOR user_info_id_seq
```

## Caveats

- Duplicate column names cannot appear in `ORDER BY`
- Pagination depends on `ROW_NUMBER()` + CTE, semantically different from MySQL's `LIMIT`
- Default schema is `dbo`; be mindful when creating tables

## Key Differences Summary

- Uses square brackets `[]` for identifier quoting
- Uses `ROW_NUMBER() OVER()` + CTE for pagination
- Automatically inserts `dbo` as the default schema
- `OUTPUT INSERTED` is similar to PostgreSQL `RETURNING`, but not used for Ignore/Update
