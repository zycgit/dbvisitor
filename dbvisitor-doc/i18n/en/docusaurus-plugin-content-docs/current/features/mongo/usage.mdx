# MongoDB Data Source Features

dbVisitor accesses MongoDB data sources via the [JDBC-Mongo](../../drivers/mongo/about) driver, based on the JDBC protocol.

**Supported capabilities:**
- Operate data using MongoDB commands ([supported command list](../../drivers/mongo/commands))
- [JdbcTemplate](#exec-command), [Builder API](#exec-lambda), [BaseMapper](#exec-mapper), [Method Annotations](#exec-annotation), [Mapper File](#exec-file)
- Object mapping, result set mapping, [rules](../../guides/rules/about), [parameter passing](../../guides/args/about), [ResultSetExtractor/RowMapper](../../guides/result/about)
- [Dynamic SQL](../../guides/core/file/dynamic_sql) tags in Mapper File, `Statement.RETURN_GENERATED_KEYS` (auto-retrieve `_id`)

**Not supported:** JDBC addBatch/executeBatch, transactions, stored procedures

## Concept Analogy

Execution results of different MongoDB commands fall into two categories:
- **Update count** — analogous to INSERT/UPDATE/DELETE, obtained via `executeUpdate`
- **Single/Multi-row results** — analogous to SELECT result sets, document queries normally include `_ID`, `_JSON` (strings), and document fields. See the driver reference for administrative and aggregate results

## Command Mode (JdbcTemplate) {#exec-command}

Use JdbcTemplate to execute MongoDB commands directly. Make sure the MongoDB data source is properly configured first — see [MongoDB Driver Usage Guide](../../drivers/mongo/usecase).

:::tip[Tip]
For more usage patterns, see the [JdbcTemplate class](../../guides/core/jdbc/about#guide). The following two features are unavailable due to driver limitations:
- JDBC Batch (use supported multi-document commands instead)
- Stored procedures
:::

```java title='Create JdbcTemplate'
JdbcTemplate jdbc = new JdbcTemplate(dataSource);
// or
JdbcTemplate jdbc = new JdbcTemplate(connection);
```

```java title='Insert data'
// Direct command
jdbc.execute("test.user_info.insert({name: 'mali', age: 26})");
// Parameterized command
jdbc.execute("test.user_info.insert(?)", new Object[] { "{name: 'mali', age: 26}" });
```

```java title='Query data'
// Query all
List<Map<String, Object>> list = jdbc.queryForList("test.user_info.find()");
// Conditional query
Map<String, Object> mali = jdbc.queryForMap("test.user_info.find({name: 'mali'})");
String json = (String) mali.get("_JSON");
```

```java title='Update data'
jdbc.execute("test.user_info.update({name: 'mali'}, {$set: {age: 27}})");
```

```java title='Delete data'
jdbc.execute("test.user_info.remove({name: 'mali'})");
```

## Builder API (LambdaTemplate) {#exec-lambda}

The Builder API provides a type-safe, fluent way to operate MongoDB with the same usage as RDBMS. For details, see [Builder API](../../guides/core/lambda/about).

```java title='Initialize'
LambdaTemplate lambda = new LambdaTemplate(dataSource);
```

```java title='Insert'
UserInfo user = new UserInfo();
user.setUid("1001");
user.setName("test_user");

int result = lambda.insert(UserInfo.class)
                   .applyEntity(user)
                   .executeSumResult();
```

```java title='Query'
// Conditional query
UserInfo user = lambda.query(UserInfo.class)
                      .eq(UserInfo::getUid, "1001")
                      .queryForObject();

// List query
List<UserInfo> users = lambda.query(UserInfo.class)
                             .like(UserInfo::getName, "test")
                             .queryForList();
```

```java title='Update'
int result = lambda.update(UserInfo.class)
                   .eq(UserInfo::getUid, "1001")
                   .updateTo(UserInfo::getName, "New Name")
                   .doUpdate();
```

```java title='Delete'
int result = lambda.delete(UserInfo.class)
                   .eq(UserInfo::getUid, "1001")
                   .doDelete();
```

## BaseMapper Interface {#exec-mapper}

`BaseMapper` provides generic CRUD methods with the same usage as RDBMS. For details, see [BaseMapper](../../guides/core/mapper/about).

```java title='Define Mapper interface'
@SimpleMapper
public interface UserInfoMapper extends BaseMapper<UserInfo> {
    // Custom methods can be added here
}
```

```java title='CRUD with Mapper'
Session session = ...;
UserInfoMapper mapper = session.createMapper(UserInfoMapper.class);

// Insert
mapper.insert(user);
// Query
UserInfo loadedUser = mapper.selectById(user.getUid());
// Update
loadedUser.setName("updated_name");
mapper.update(loadedUser);
// Delete
mapper.deleteById(user.getUid());
```

## Annotation Mode {#exec-annotation}

:::tip[Tip]
For the [Core API annotations](../../guides/core/mapper/about), all annotations work normally on MongoDB except `@Call`.
:::

```java title='1. Define object'
@Table("user_info")
public class UserInfo {
    @Column(value = "uid", primary = true)
    private String uid;
    @Column("name")
    private String name;
    ... // getter/setter omitted
}
```

```java title='2. Define Mapper interface'
@SimpleMapper()
public interface UserInfoMapper {
    @Insert("test.user_info.insert(#{info, typeHandler=net.hasor.dbvisitor.types.handler.json.JsonTypeHandler})")
    int saveUser(@Param("info") UserInfo info);

    @Query("test.user_info.find({uid: #{uid}})")
    UserInfo loadUser(@Param("uid") String uid);

    @Delete("test.user_info.remove({uid: #{uid}})")
    int deleteUser(@Param("uid") String uid);
}
```

```java title='3. Create and use Mapper'
Configuration config = new Configuration();
Session session = config.newSession(dataSource);

UserInfoMapper mapper = session.createMapper(UserInfoMapper.class);
```

### Mapping ObjectId {#object-id}

MongoDB's `_id` field is typically of `ObjectId` type, while Java objects usually use `String`.

```java title='Define object (ObjectId mapping)'
@Table("user_info")
public class UserInfo {
    @Column(value = "_id", primary = true, whereValueTemplate = "ObjectId(?)")
    private String id;

    @Column("name")
    private String name;
    ...
}
```

```java title='Mapper definition (query using ObjectId)'
@SimpleMapper()
public interface UserInfoMapper {
    @Query("test.user_info.find({_id: ObjectId(#{id})})")
    UserInfo loadById(@Param("id") String id);
}
```

### _id Backfill {#id-fill}

MongoDB returns the inserted document's `_id` when inserting documents. The MongoDB documentation states that `insertOne()` returns a value containing `insertedId`; if the document does not specify an `_id`, MongoDB or the driver generates one. See [MongoDB insertOne documentation](https://www.mongodb.com/docs/manual/reference/method/db.collection.insertone/).

dbVisitor's jdbc-mongo adapter converts MongoDB `insertOne` / `insertMany` inserted ids to JDBC generated keys with the column name `_id`. Therefore, `useGeneratedKeys` can be used in Mapper XML / Annotation to backfill `_id`.

```xml title='MongoDB Mapper XML _id backfill'
<insert id="insertUser"
        useGeneratedKeys="true"
        keyProperty="id">
    test.user_info.insertOne({name: #{name}, age: #{age}})
</insert>
```

```java title='MongoDB Annotation _id backfill'
@Insert(
    value = "test.user_info.insertOne({name: #{name}, age: #{age}})",
    useGeneratedKeys = true,
    keyProperty = "id"
)
int insertUser(UserInfo user);
```

The Mapper configuration above omits `keyColumn` and reads the first returned column. The adapter does not support JDBC overloads taking column-name arrays, so Lambda / BaseMapper `KeyType.Auto` backfill cannot be used directly. Map an existing ObjectId as a query primary key:

```java
@Table("user_info")
public class UserInfo {
    @Column(value = "_id", primary = true, whereValueTemplate = "ObjectId(?)")
    private String id;

    @Column("name")
    private String name;
}
```

MongoDB's generated keys come from the driver adapter's insert result, not from `MongoDialect` SQL concatenation. `MongoDialect` handles Mongo command construction, conditions, sorting, pagination, and other syntax differences; `_id` backfill is handled by the jdbc-mongo command execution layer.

### Paginated Queries {#pagination}

Add a `Page` parameter to Mapper methods for paginated queries.

```java title='Mapper definition'
@SimpleMapper()
public interface UserInfoMapper {
    @Query("test.user_info.find({name: #{name}})")
    List<UserInfo> queryByName(@Param("name") String name, Page page);
}
```

```java title='Paginated call'
Page page = new PageObject();
page.setPageSize(10);

List<UserInfo> list = mapper.queryByName("mali", page);
```

## File Mode (Mapper File) {#exec-file}

```java title='1. Define object'
@Table("user_info")
public class UserInfo {
    @Column(value = "uid", primary = true)
    private String uid;
    @Column("name")
    private String name;
    ... // getter/setter omitted
}
```

```xml title='2. Define Mapper file'
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//dbvisitor.net//DTD Mapper 1.0//EN"
"https://www.dbvisitor.net/schema/dbvisitor-mapper.dtd">
<mapper namespace="net.test.dto.UserInfoMapper">
    <insert id="saveUser">
        test.user_info.insert(#{info, typeHandler=net.hasor.dbvisitor.types.handler.json.JsonTypeHandler})
    </insert>

    <select id="loadUser" resultType="net.test.dto.UserInfo">
        test.user_info.find({uid: #{uid}})
    </select>

    <delete id="deleteUser">
        test.user_info.remove({uid: #{uid}})
    </delete>
</mapper>
```

```java title='3. Define Mapper interface'
@RefMapper("/path/to/mapper.xml")
public interface UserInfoMapper {
    int saveUser(@Param("info") UserInfo info);

    UserInfo loadUser(@Param("uid") String uid);

    int deleteUser(@Param("uid") String uid);
}
```
