# Key Generation

MySQL generates primary keys with `AUTO_INCREMENT`; dbVisitor can assign the generated value to the entity after insertion.

:::info[Note]
For general configuration, see [Generated Keys](../../guides/core/mapper/annotation_insert#generated-keys).
:::

## Using AUTO_INCREMENT

```sql
CREATE TABLE user_info (
    id INTEGER PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(64)
) ENGINE=InnoDB;
```

<Tabs>
<TabItem value="identity-lambda" label="Fluent API" default>

```java
@Table("user_info")
public class UserInfo {
    @Column(value = "id", primary = true, keyType = KeyType.Auto)
    private Integer id;
    @Column("name")
    private String name;
}
```

```java
UserInfo user = new UserInfo();
user.setName("mali");

LambdaTemplate lambda = ...;
lambda.insert(UserInfo.class).applyEntity(user).executeSumResult();

Integer id = user.getId(); // Auto-backfilled
```

Ignore and Update do not guarantee a new key for every input entity. See [Insert Conflicts](./conflict.mdx) for strategy semantics and usage.

</TabItem>
<TabItem value="identity-annotation" label="Method Annotations">

```java title='Method Annotations'
@Insert(value = "INSERT INTO user_info (name) VALUES (#{name})",
        useGeneratedKeys = true, keyProperty = "id", keyColumn = "id")
int insertUser(UserInfo user);
```

</TabItem>
<TabItem value="identity-xml" label="Mapper File">

```xml title='Mapper File'
<insert id="insertUser" useGeneratedKeys="true" keyProperty="id" keyColumn="id">
    INSERT INTO user_info (name) VALUES (#{name})
</insert>
```

</TabItem>
</Tabs>

:::caution[Note]
After inserting multiple entities, read each entity's ID; do not infer IDs from the first value. Rows skipped or updated by an insert-conflict strategy may not receive a generated ID.
:::
