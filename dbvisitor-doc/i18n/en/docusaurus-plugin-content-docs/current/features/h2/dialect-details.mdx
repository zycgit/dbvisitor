# H2 Dialect Details

## Pagination SQL

H2 uses `LIMIT ? OFFSET ?` (same as PostgreSQL):

```sql
SELECT ... LIMIT ? OFFSET ?
```

## Count SQL

```sql
SELECT COUNT(*) FROM (original query) as TEMP_T
```

## Identifier Quoting

Uses double quotes `"`:

```sql
SELECT * FROM "users" WHERE "name" = ?
```

## Write Conflict Strategies

| Strategy | SQL Syntax | PK Required |
|------|---------|:----------:|
| Into | `INSERT INTO ... VALUES (...)` | No |
| Ignore | `MERGE INTO ... USING (VALUES ...) ... WHEN NOT MATCHED THEN INSERT ...` | Yes |
| Update | `MERGE INTO ... KEY (...) VALUES (...)` | Yes |

Ignore uses a matching condition to insert unmatched records only; Update uses H2's `MERGE INTO ... KEY (...) VALUES (...)` syntax.

## Generated Key Strategy

| Scenario | GeneratedKeyStrategy |
|------|---------------------|
| No backfill columns | `JdbcBatch` |
| With backfill columns (any strategy) | `OneByOne` |

## Sequences

H2 implements `SeqSqlDialect`, using the same syntax as DB2:

```sql
VALUES NEXT VALUE FOR user_seq
```

## Testing Scenario Recommendations

- For local development, create an in-memory database with `jdbc:h2:mem:demo;DB_CLOSE_DELAY=-1`
- H2 compatibility mode can simulate MySQL/PostgreSQL behavior
- But note that pagination syntax may differ from real databases
- H2 compatibility modes do not replace type, transaction and SQL validation against your target database

## Key Differences Summary

- Pagination syntax same as PostgreSQL (`LIMIT ? OFFSET ?`)
- Ignore and Update use different MERGE forms
- Supports sequences (same syntax as DB2: `VALUES NEXT VALUE FOR`)
- Uniform row-by-row execution when backfill is needed
- In-memory databases support local development without a separate service
