# Dialect Details

## Pagination SQL

DB2 uses `ROWNUMBER() OVER()` nested query for pagination:

```sql
SELECT * FROM (
  SELECT TMP_PAGE.*, ROWNUMBER() OVER() AS ROW_ID FROM (
    original query
  ) AS TMP_PAGE
) TMP_PAGE WHERE ROW_ID BETWEEN ? AND ?
```

Parameters: `ROW_ID BETWEEN startRow+1 AND endRow` (1-based).

## Count SQL

```sql
SELECT COUNT(*) FROM (original query) as TEMP_T
```

## Identifier Quoting

Uses double quotes `"`:

```sql
SELECT * FROM "users" WHERE "name" = ?
```

## LIKE Syntax

Uses `CONCAT` function (same as MySQL):

| LIKE Type | Generated SQL |
|-----------|-----------|
| Full fuzzy | `CONCAT(CONCAT('%', ?), '%')` |
| Left fuzzy | `CONCAT('%', ?)` |
| Right fuzzy | `CONCAT(?, '%')` |

## Write Conflict Strategies

| Strategy | SQL Syntax | PK Required |
|------|---------|:----------:|
| Into | `INSERT INTO ... VALUES (...)` | No |
| Ignore | `MERGE INTO ... WHEN NOT MATCHED THEN INSERT ...` | Yes |
| Update | `MERGE INTO ... WHEN MATCHED THEN UPDATE ... WHEN NOT MATCHED THEN INSERT ...` | Yes |

## Generated Key Strategy

| Scenario | GeneratedKeyStrategy | Notes |
|------|---------------------|------|
| No backfill columns | `JdbcBatch` | Regular batch |
| With backfill columns (any strategy) | `OneByOne` | Conservative row-by-row |

When backfill columns exist, uniformly uses `OneByOne`. Reason: IBM documentation states that under some DB2 configurations, a `PreparedStatement` prepared for generated keys return cannot be used for batch updates.

## Sequences

DB2 implements `SeqSqlDialect`:

```sql
VALUES NEXT VALUE FOR user_seq
```

With schema:

```sql
VALUES NEXT VALUE FOR "app"."user_seq"
```

Used in object mapping via `@KeySeq("user_seq")` + `KeyType.Sequence`.

## Key Differences Summary

- Pagination similar to Oracle (ROWNUMBER nesting), but syntax is `BETWEEN ? AND ?`
- Uniformly uses row-by-row execution when primary key backfill is needed (does not trust batch generated keys)
- Supports sequences: `VALUES NEXT VALUE FOR seq`
- LIKE uses `CONCAT` function
- MERGE conflict strategies require primary key columns
