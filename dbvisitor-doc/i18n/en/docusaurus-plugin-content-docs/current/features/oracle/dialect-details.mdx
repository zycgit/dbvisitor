# Dialect Details

## Pagination SQL

Oracle uses ROWNUM nested queries for pagination:

```sql
SELECT * FROM (
  SELECT TMP.*, ROWNUM ROW_ID FROM (
    original query
  ) TMP WHERE ROWNUM <= ?
) WHERE ROW_ID > ?
```

Parameters: `ROWNUM <= endRow` and `ROW_ID > startRow`.

## Count SQL

```sql
SELECT COUNT(*) FROM (original query) TEMP_T
```

Note: Oracle's count subquery does not use the `as` alias keyword — writes `TEMP_T` directly.

## Identifier Quoting

Uses double quotes `"`:

```sql
SELECT * FROM "users" WHERE "name" = ?
```

## Write Conflict Strategies

| Strategy | SQL Syntax | PK Required |
|------|---------|:----------:|
| Into | `INSERT INTO ... VALUES (...)` | No |
| Ignore | `MERGE INTO ... USING (SELECT ... FROM dual) SRC ON (...) WHEN NOT MATCHED THEN INSERT ...` | Yes |
| Update | `MERGE INTO ... USING (SELECT ... FROM dual) SRC ON (...) WHEN MATCHED THEN UPDATE ... WHEN NOT MATCHED THEN INSERT ...` | Yes |

Oracle's MERGE uses `FROM dual` as the virtual source table.

## Generated Key Strategy

Oracle dialect **uniformly uses `OneByOne`** (row-by-row execution), regardless of whether backfill columns exist or what conflict strategy is used. This does not mean Oracle JDBC itself lacks batch support:

| Scenario | GeneratedKeyStrategy |
|------|---------------------|
| All scenarios | `OneByOne` |

Reason: Oracle JDBC's batch generated keys behavior is unstable. If `Statement.RETURN_GENERATED_KEYS` is used without specifying `keyColumn`, it returns the `ROWID` pseudo-column instead of the business primary key.

## Sequences

The built-in Oracle dialect does not implement `SeqSqlDialect`, so `@KeySeq` + `KeyType.Sequence` cannot be used directly. Read sequences using Mapper XML `selectKey` or `@SelectKeySql`:

```sql
SELECT user_info_seq.NEXTVAL AS id FROM dual
```

## Caveats

- `RETURNING INTO` is an OUT parameter model, not equivalent to PostgreSQL `RETURNING`; do not use `generatedKeySource="resultSet"`
- Always explicitly specify `keyColumn` on INSERT to correctly backfill business primary keys
- Dameng's MERGE is highly consistent with Oracle syntax (also uses `FROM dual`)

## Key Differences Summary

- The dialect uses `OneByOne` for all insert scenarios
- Pagination uses ROWNUM nesting; write your own SQL or custom dialect for other pagination forms
- MERGE uses `FROM dual` to construct a virtual source table
- Does not implement `SeqSqlDialect`; sequences go through the `selectKey` channel
